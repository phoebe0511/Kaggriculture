# Kaggriculture — 專案章程

Kaggle 農場模擬對戰比賽的 AI。目標：**上榜（前 10 名）。**

> **這份文件假設你是軟體工程師，但沒做過 ML。**
> 所有 ML 名詞第一次出現都會用白話解釋。
> 完整的概念說明在 `docs/ml-primer.md`，**建議先讀那份再讀架構**。

---

## 1. 這個比賽在幹嘛

兩個玩家各自經營一座農場，比誰在 30 天賽季結束時錢多。

你要交的**不是一個模型檔，是一支程式**。Kaggle 會把你的程式跟別人的程式配對，各自跑一局，看誰賺得多。

```
Kaggle 呼叫你的程式：「現在是第 341 回合，這是農場現況，你要做什麼？」
你的程式回答：「HARVEST，座標 (4,7)」
                    ↓
              重複 720 次
                    ↓
              誰錢多誰贏
```

所以本質上你在寫一個 **`act(現況) → 動作` 的函式**，只是這個函式要很聰明。

## 2. 基本規格

| 項目 | 內容 |
|---|---|
| 對戰形式 | 1v1，兩人各自經營**獨立農場** |
| 賽季長度 | 30 天 = **720 回合**，1 回合 = 遊戲內 1 小時 |
| 單局分數 | 期末現金（`bank`） |
| 排名 | ladder skill rating，多局累積 |
| 市場 | **共用**，價格隨供需變動 |
| 獎金 | 總額 $50,000，前 10 名各 $5,000 |
| Entry / Team Merger 截止 | 2026-09-23 |
| Final Submission 截止 | 2026-09-30；之後約跑到 10-15 收斂 |
| 團隊 | 2 人 |
| 硬體 | i7-14700F（20 核 / 28 執行緒）+ GPU；Kaggle T4 每週 30 小時 |

### 動作清單（18 個，來自遊戲畫面）

```
PASS                              什麼都不做
NORTH  SOUTH  EAST  WEST          移動（會消耗一個回合）
PLANT  WATER  FERTILIZE  HARVEST  種田
DIG                               整地
BUILD_COOP  BUILD_PASTURE         蓋雞舍 / 牧場
FEED  CARE  COLLECT_FERTILIZER    養動物
PICKUP  PLACE  DROP               搬東西
```

### 從這張清單看出的三件事

**（1）真正稀缺的是時間，不是錢。**
移動要花掉一個回合。農夫從農舍走到最遠的田，成本是好幾個遊戲小時。

**（2）收成先進 unit inventory，每日結算會自動入庫。**
只有當天就要賣、餵動物／施肥要先補給，或 shed 可能超過 100 時，才需要安排
`PICKUP` / `PLACE` / `DROP`。溢出的物品會直接消失。

**（3）這題的數學本質是「排班 + 送貨路線規劃」。**
一群人、一堆待辦任務、每個任務有時間窗（作物什麼時候熟、動物什麼時候要餵），要排出最有效率的行程。作業研究裡叫 VRP（Vehicle Routing Problem）。

> ⚠️ 這張清單裡**沒有 BUY / SELL / HIRE**。買地、雇工、賣東西應該走另一條路徑。**未確認，見 `docs/unknowns.md` #1。**

## 3. 得分 vs 排名（很多設計都是從這裡推出來的）

```
單局分數     = 期末現金（絕對數字）
     ↓
單局勝負     = 我的錢 vs 對手的錢（相對）
     ↓
Leaderboard = skill rating（多局累積）
```

**你賺 50,000，對手賺 60,000 → 這局算輸。**

兩個直接後果：

- 我們要 AI 學的是「我比對手多賺多少」，不是「我賺多少」。否則它會把「這局市場行情好」跟「我下得好」搞混。
- **落後時要賭，領先時要保守。** 剩三天大幅落後的話，穩穩縮小差距沒有用（還是輸），該押高風險高報酬的選項。這個結論在「最大化自己的錢」的框架下是推不出來的。

## 4. 我們的做法：一句話版本

> **先寫一支笨但正確的 AI，讓它自己跟自己打幾千局，
> 再訓練一個神經網路去模仿它，
> 然後讓神經網路去打，產生更好的棋譜，再訓練一次。
> 重複五輪。**

這叫 **Expert Iteration**，AlphaZero 用的就是這套的變形。

完整說明在 `docs/ml-primer.md` §4。

### 為什麼需要神經網路

大部分東西我們**用讀的就好**：作物幾小時成熟、賣 100 單位價格會掉多少、走一格花多久——這些公式都寫在遊戲引擎的原始碼裡（開源的）。這些不需要「學」。

只有一件事讀不到：

> **現在這個局面，打到最後我會比對手多賺多少？**

這沒有公式，只能從大量對局裡學。這就是神經網路唯一的工作。

### 神經網路在這裡的角色不是「取代思考」

而是**讓思考變快**。

我們的 AI 每回合會做搜尋（試算「如果我這樣做，接下來會怎樣」）。但時間有限，只能試幾百種可能。神經網路的作用是：

- 告訴搜尋「這幾個動作比較值得試」→ 不用亂試
- 告訴搜尋「試到這裡就好，這個局面大概值這麼多」→ 不用算到第 720 回合

結果是同樣的時間內，能看得更深。

## 6. 名詞對照表

| 名詞 | 白話 |
|---|---|
| **agent** | 我們寫的那支會玩遊戲的程式 |
| **engine** | Kaggle 的遊戲引擎（開源，可以讀原始碼） |
| **episode** | 一局遊戲（720 回合） |
| **replay** | 一局的完整記錄，每回合的狀態和動作都有 |
| **observation / obs** | 引擎給我們的「現況」，一個 dict |
| **action** | 我們回傳的動作 |
| **submission** | 交到 Kaggle 的那支程式 |
| **self-play** | 讓我們的 AI 自己跟自己打 |
| **model / 模型** | 訓練出來的神經網路（說穿了就是一堆數字） |
| **checkpoint** | 訓練過程中存下來的模型檔 |
| **policy** | 「這局面該做什麼」的函式 |
| **value** | 「這局面值多少分」的函式 |
| **PyTorch / torch** | 訓練神經網路用的套件（很肥，只在自己電腦用） |
| **numpy** | Python 標準數值運算套件（很輕，比賽時用這個） |
