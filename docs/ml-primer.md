## 1. 神經網路是什麼

**它就是一個函式。**

```
輸入：一堆數字      →  [黑盒子]  →  輸出：一堆數字
```

黑盒子裡面是什麼？就是**矩陣乘法**，一層接一層：

```python
def 神經網路(x):
    x = x @ W1 + b1;  x = relu(x)   # relu 就是 max(0, x)
    x = x @ W2 + b2;  x = relu(x)
    x = x @ W3 + b3
    return x
```

就這樣。`W1 W2 W3 b1 b2 b3` 是一堆數字（叫**參數**或**權重**），我們的網路大概有 100 萬~300 萬個。

**「訓練」就是自動調這些數字**，讓函式的輸出接近我們要的答案。

### 類比

如果你寫過曲線擬合（給一堆點，找一條線）：

```
曲線擬合：      找 a, b 讓 y = ax + b 最接近資料      → 2 個參數
神經網路：      找 100 萬個參數讓輸出最接近答案         → 100 萬個參數
```

**概念上完全一樣，只是參數多了 50 萬倍，而且函式形狀更彎。**

沒有魔法。它不會「理解」什麼，它只是一個被調到很準的函式。

## 2. 訓練 vs 推論 ≈ 編譯 vs 執行

這是最重要的類比，**很多規則都是從這裡來的**：

| | 訓練 (training) | 推論 (inference) |
|---|---|---|
| 做什麼 | 調那 100 萬個參數 | 拿調好的參數算一次答案 |
| 何時 | 在我們自己電腦，跑幾小時~幾天 | 比賽時，每回合幾毫秒 |
| 用什麼 | GPU + PyTorch | CPU + numpy |
| 類比 | **編譯** | **執行** |
| 產出 | 一個檔案（`.npz`，就是那堆數字） | 一個動作 |

```
自己電腦：   訓練資料 ──[PyTorch + GPU]──→  weights.npz
                                                │
Kaggle：                                        ▼
             現況 ──[numpy 讀 weights.npz]──→ 動作
```

### 所以「submission 不准 import torch」的意思是

PyTorch 是**訓練工具**，2GB 起跳，載入要好幾秒。

但比賽時我們只是要「執行」——讀那堆數字做矩陣乘法。numpy 就夠了，而且很輕。

**你不會把整套編譯工具鏈塞進 production binary。同樣道理。**

如果程式一啟動就花 5 秒載 torch，這 5 秒是從你的時間額度扣的，第一回合就可能超時判輸。

## 3. 我們的網路要輸出兩樣東西

### Policy（策略）—「該做什麼」

```
輸入：農場現況
輸出：18 個動作各自的分數
      PASS 0.02 | NORTH 0.31 | HARVEST 0.45 | ...
```

**這不是最終答案，是「建議」。** 用途是引導搜尋——後面會講。

### Value（估值）—「現在局面值多少」

```
輸入：農場現況
輸出：一個數字，例如 +3200
      意思是「照這樣打下去，我最後會比對手多賺 3200」
```

> ⚠️ 注意是**差值**，不是我的錢。
> 用絕對金額當答案的話，網路會把「這局市場行情好」跟「我下得好」混在一起學。

### 為什麼需要 value：因為我們算不到最後

搜尋時我們想試「如果我這樣做，接下來會怎樣」。但一路推到第 720 回合是不可能的（分支太多）。

所以推個 20 回合就停下來，**用 value 猜「從這裡開始大概值多少」**。

```
現在 ──推 20 回合──→ 某個局面 ──[value 網路]──→ +3200
                                    ↑
                          不用真的打到 720 回合
```

**這就是 value 網路存在的唯一理由。**

## 4. Expert Iteration：像 bootstrapping compiler

這是我們的訓練方法。你如果知道**自舉編譯器**（用舊版編譯器編譯出更好的新版編譯器，再用新版編譯自己），這完全是同一個結構。

```
第 0 代：手寫一支笨但正確的 AI（規則式，if-else 那種）
            │
            ├─ 讓它自己跟自己打 5,000 局，記錄每一步
            ▼
        訓練網路模仿它
            │
第 1 代：網路 + 搜尋
            │  ⚡ 這裡已經比第 0 代強了
            │     因為搜尋會放大網路的判斷
            │
            ├─ 用第 1 代打 5,000 局，記錄
            ▼
        重新訓練
            │
第 2 代 → 第 3 代 → ... → 第 5 代
```

### 為什麼「網路 + 搜尋」會比它模仿的對象強

網路學會了老師的直覺（大概該往哪個方向想）。

但網路**不只是照抄**——它把直覺當起點，然後真的去試算幾百種可能，選最好的。

```
老師（第 0 代）：憑規則直接出招
網路 + 搜尋：   憑直覺挑出 5 個值得試的 → 各推 20 回合 → 選最好的
```

**直覺 + 驗算 > 純直覺。** 這就是每一代都會進步的原因。

### 為什麼選這個方法（而不是 RL）

你可能聽過強化學習（RL / PPO），讓 AI 從零自己摸索。我們**不用**，理由是：

| | Expert Iteration | 從零 RL（PPO） |
|---|---|---|
| 每一代會不會退步 | **不會**（打不贏舊版就丟掉） | **會**，可能訓兩週後比手寫版還爛 |
| 出問題能不能查 | 能（policy / value / 搜尋可分開測） | 很難，只能重訓再賭 |
| 需要暖身 | 要先有一支笨 AI | 不用 |
| 六週內能不能成 | 高機率 | 低機率 |

**「每一代保證不退步」是我們選它的關鍵。** 六週的專案不能承受「訓了兩週結果變爛」。

## 5. 搜尋：有寬度上限的 BFS

比賽時每回合的流程：

```
1. 網路跑一次 → 得到 policy（動作建議）和 value（局面估值）
                  ↑ 這一步就已經產出一個可用的動作了，是保底

2. 還有時間 → 用 policy 挑出前 5 個動作，各推幾步看看
              每個分支的末端用 value 評分

3. 時間到 → 交出目前算出來最好的
```

這叫 **beam search**：就是 BFS，但每層只保留分數最高的前 K 個節點，其他剪掉。K 就是「beam width」。

**因為第 1 步就已經有答案了，所以永遠不會超時。** 時間不夠就用網路的直覺出招，時間多就多想幾步。這是 anytime 演算法——隨時可以叫停並取得目前最佳解。

## 6. 為什麼大部分東西「不用學」

這是我們跟一般 ML 專案最大的不同：**遊戲引擎是開源的，規則可以直接讀。**

| 想知道 | 怎麼得到 |
|---|---|
| 小麥幾小時成熟 | 讀原始碼的常數 |
| 賣 100 單位價格掉多少 | 讀原始碼的公式 |
| 走一格花多少時間 | 讀原始碼 |
| 雇一個工人划不划算 | 費率 ÷ 產能，兩個常數相除 |
| **這局面最後我會贏多少** | ❌ 沒公式，**只能學** |

**用神經網路去逼近一個你能直接讀到的公式，只會得到一個更慢、更不準、更難 debug 的版本。**

這就像明明有 API 文件，卻要用機器學習從流量猜 API 行為。沒道理。

所以：**能讀就讀，讀不到才學。** 我們只學最後那一項。

## 7. 這個專案裡真正難的部分不是 ML

老實說，ML 的部分**程式碼很少**——網路定義加訓練迴圈大概 300 行，而且大半是照抄樣板。

難的是這些，全部是純軟體工程：

| 難點 | 為什麼難 |
|---|---|
| **產資料的速度** | 一代要 5,000 局 × 720 回合 = 360 萬次模擬。慢的話整個循環卡死。要多行程、要避開 GIL、要 profile |
| **不要超時** | 每回合幾秒的硬上限，720 回合累積 |
| **不要靜默失敗** | 引擎遇到做不到的動作會裝作沒看見 |
| **兩人不要互相打爆** | 介面凍結、版本管理 |
| **改動有沒有變強** | 隨機性很大，要用統計方法判定 |

**你們兩個的技能剛好對這些難點。ML 的部分是最不需要擔心的。**

## 8. 還會遇到的名詞

| 名詞 | 白話 |
|---|---|
| **epoch** | 把訓練資料完整掃過一遍 |
| **batch** | 一次餵給網路的資料筆數（一次算 256 筆比一次算 1 筆有效率得多） |
| **loss** | 「現在答錯多少」的數字，訓練就是想辦法讓它變小 |
| **CNN** | 專門處理格狀資料的網路結構（我們的農場是格子，所以用它） |
| **MLP** | 最基本的網路結構，處理一維數字（現金、庫存這種） |
| **head** | 網路的分支輸出。同一個網路可以有多個 head（我們有 policy head 和 value head） |
| **overfitting** | 網路把訓練資料背起來了，遇到沒看過的就爛掉 |
| **inference server** | 一個獨佔 GPU 的行程，其他行程把資料丟給它算（避免每個行程各載一份模型） |
| **ONNX** | 一種「只執行不訓練」的模型格式，numpy 手寫的替代方案 |
