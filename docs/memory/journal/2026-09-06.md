## §88 PPO 練不起來的原因：接手的 critic 學的是另一個量

夥伴問「PPO 練不起來，你有作檢查嗎」。**沒有** —— 前面五次（含今天兩次）

### 88.1 實作本身沒有 bug

```

                    （既有的 test_update_reproduces_rollout_logprob）
```

### 88.2 🩸 真正的原因：value head 預測的是「期末現金 / 100k」

`model/train.py:12` 寫著監督式的 value 標籤是 **`期末現金 / 100k`**。
PPO 的 value 目標是 **`剩下的 margin / REWARD_SCALE`**。兩個不是同一個量
換單位：一個是絕對值、恆正，一個是相對差、輸的時候是負的。

`load_init` 把 60 個張量**全部**吃進去、跳過 0 個 —— value head 原封不動
被沿用。用 `ckpt-cma1-round4-tgt` 對 `cma1-g50-wt` 各跑一局（greedy）：

```
seed      期末現金   /100k   value 中位   value 末  |  PPO 的目標   兩者相關
900000    48,887   0.489     0.451     0.531   |    -1.274      +0.29
900001    60,019   0.600     0.551     0.715   |    -1.671      +0.26
900002    90,344   0.903     0.781     0.938   |    -1.208      -0.48
900003    79,724   0.797     0.694     0.729   |    -1.757      -0.21
```

value 的中位數幾乎等於「自己的期末現金 / 100k」，跟 PPO 要的東西
**幾乎不相關、有時候是負的**。四局的預測範圍都是 +0.25~+1.0，實際回報
都是 −2.8~−0.5。

### 88.3 後果不是 value 不準，是它把 policy 一起拖垮

網路是共用軀幹接三個頭（`model/net.py`：`value_head` 掛在池化後的特徵上）。
訓練 log 第 0 輪：

```
policy loss  -0.036
value  loss  +5.503      <- 大 150 倍
```

`vf_coef 0.5` 之下 value 那一項貢獻 2.75、policy 只有 0.036。梯度幾乎
全部來自「把 value head 從舊目標搬到新目標」，**共用軀幹被它重塑，
policy 的三個頭跟著壞掉**。這解釋了三件先前看不懂的事：

```
ent-coef 0 之下 entropy 還從 11.0 漲到 15.1   軀幹被重塑，policy 的頭跟著亂
要到第 40~50 輪 policy 才開始往回爬          那時 value 已經收斂（ev 0.94）
混合式看起來比較好（92,136）                 破壞照樣發生，但工人動作由 gen0
                                             出，軀幹被打亂只影響 market head
```

旁證：`slow-lr`（lr 3e-5 -> 5e-6，其餘不動）**沒有崩** ——
it 4/9/14 是 60,502 / 67,250 / 62,310，都在基準 65,679 附近震盪；
對照 lr 3e-5 那支 it 19 已經掉到 39,265。policy 走得慢，value 的梯度
就來不及把軀幹拖垮。

### 88.4 改了什麼

```
model/ppo.py        ppo_loss / update 多一個 policy_coef，設 0 就只剩 value loss
model/ppo_train.py  --value-warmup N   前 N 輪只練 value head
                    --reset-value      開跑前重新初始化 value head 那兩層
                    --value-lr         暖身階段的 lr（沒有信賴區域要顧）
tests/test_ppo.py   +2 項：暖身後動到的權重**只能是** value_head.*，
                    而且 policy 的機率要逐項不變
```

🩸 **軀幹是共用的，所以「凍結 policy」不能只把 policy loss 關掉** ——
optimiser 也只能收 `net.value_head.parameters()`。兩件事缺一，暖身自己
就會把 policy 弄壞。測試釘的就是這一點。
