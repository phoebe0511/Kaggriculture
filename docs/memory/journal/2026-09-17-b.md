## §120 Lambda 重現失敗：2 seed × 2 λ

換 seed（`--seed 8156 --seed0 905120`，eval-seed0 不變仍是預設 900,000）跑第二對，
其餘與 §117.1 逐字相同。

```
                 λ=0.998      phased     λ 效果
seed 4382        -33,896     -31,763     +2,133
seed 8156        -31,765     -32,358       -593
seed 效果          +2,131        -595

λ 效果 兩個 seed: +2,133 / -593   平均 +770   同向: 否
seed 效果 兩個設定: +2,131 / -595   平均 +768
λ 效果 / seed 效果 = 1.00
```

🩸 **光是換 seed，同一個 baseline config 就差 +2,131** —— 跟 §117 量到的
intervention effect +2,133 同量級。而 `lam2-base`（沒做任何 intervention）的
12 點平均 -31,765，跟第一次 treatment 臂 `lam-split` 的 -31,763 只差 2。

由兩個估計反推的 λ 效果 SD 是 1,928，平均 +770 -> 80% power 每臂約需 **50 條 run**
（約 100 小時）。n=2 的 95% CI 是 `+770 ± 17,325`，沒有資訊量。

### 120.1 但 learning signal 兩次都重現

```
                        seed 4382                seed 8156
                    base  ->  split          base  ->  split
逐步殘差佔 Var(adv)  5.82% -> 16.95%        5.55% -> 15.82%
advantage sd        0.6849 -> 0.3095       0.6731 -> 0.3252
lag1（軌跡內）      +0.9221 -> +0.8713     +0.9241 -> +0.8773
積分自相關時間        365 -> 138 步           370 -> 155 步
有效獨立 advantage／輪  32 -> 83               31 -> 74
action-level r      +0.1346 -> +0.2012     +0.1419 -> +0.1918
```

λ 對 advantage 結構的作用是**機械的**，不受 seed 影響。兩個 baseline 彼此幾乎
相同、兩個 treatment 也是。

### 120.2 判定改為 B

§117 判 A 的條件是「learning signal 改善**而且** held-out greedy margin 也改善」。
第二對的 margin 是 −593。兩次合起來最接近 **B —— learning signal 改善，但
downstream margin 沒改善**。

不等於 λ 對 margin 沒有效果，等於：任何 margin 效果都小於兩對 run 能分辨的下限。

⚠️ §117 的 §117.7 限制一、二說中了。那個 t=2.401、p=0.035 量的是「這一對 run
之間差異穩不穩定」，不是「重跑會不會一樣」。

## §125 🩸 同回合衝突：規則沒走對，已無條件修掉

### 125.1 發現

比對「發出的 PLANT 動作」與「真的長出來的作物」（`tools/plant_fail.py`）：

```
                PLANT 動作   cohort 數    成功率    買種子量
kaggle 134 條      190.2      189.1    99.4%     201.3
cma1-g50-wt       182.1      182.1   100.0%     208.4
PPO ckpt-140      183.3      137.0    74.7%     251.7
PPO lam2-base     136.1      114.5    84.1%     233.7
```

PPO 每局 183 次 PLANT 有約 46 次白做，而它買的種子比誰都多。

### 125.2 原因：`legal_unit_mask` 一回合只算一次

mask 用**回合開始前**的狀態算一次（`contracts.py:931` 的
`tile is None and seeds.get(item,0) > 0`），同一回合裡 unit 之間的互相影響完全
沒被考慮。兩種衝突：

```
1 同格   多個 unit 站在同一格都選 PLANT。第一個種下去那格就不是空的，其餘被拒絕。
         實測 seed 900000：34 個失敗回合**全部**是這種，沒有同格重疊的失敗是 0。
2 種子   種子是全農場共用的一份存量。次要 —— 剩餘失敗裡 30/36 種子綽綽有餘
         （有一筆 TOMATO 存量 40 顆仍失敗）。
```

🩸 我一開始只看到種子那條就下結論，錯了。同格才是主因。

### 125.3 修法（已合入，無條件生效，沒有旗標）

```
contracts.py            PLANT_OP / turn_guard_state() / turn_guard()
                        合法性看 mask 不看 logp —— masked_log_softmax 壓的是
                        -1e9 不是 -inf；並複製「整列全 False 退回全部合法」
agents/ppo_agent.py     market 先解碼（才知道這回合買幾顆種子）再逐 unit 重選
harness/ppo_rollout.py  同一個函式，兩邊一致
```

訓練側被 guard 改掉的 unit 標成 `op_exec=False`：logprob 仍記**取樣到**的那個 op
（guard 當成動作投影、環境的一部分，跟 `step_toward` 同一個處理），`--op-exec-only`
開著時不進 joint logprob。

種植成功率 **0.766 -> 0.997**。

### 125.4 🩸 我預測錯了：修好不等於多出作物

t=0 flag replay（ckpt-140 固定、20 局同 seed，完整數字在 `temp/guard_t0_result.txt`）：

```
crop_tile_turns  14,899 -> 15,287   比 1.026     <- 只 +2.6%
整局平均空地率      0.4721 -> 0.4684
margin           -40,326 -> -34,739  配對差 +5,587
                 SD 21,344  SE 4,773  t=1.171  中位數差 +408  正/負 10/10
```

我先前說「成功率修到 1.0，cohort 數會從 137 升到 183」。**錯的。** 被擋下的 unit
不會在別處種成 —— 兩個 unit 站同一格，那一格本來就只種得下一株。擋掉第二個只是讓
它改做別的事。我把「浪費的動作」誤當成「失去的作物」。

margin 的 +5,587 不能當證據（中位數 +408、10 勝 10 負、逐局差 −22,506 ~ +50,081）。

### 125.5 為什麼還是要修

送出引擎會拒絕的動作**不是策略選擇，是沒照規則走**。這不該用 margin 當判準去否決 ——
n=20 的 SE 是 4,773，本來就量不到這個尺度。這條線之後照「把規則走對」處理，
不再做 baseline 對照、不再用單一指標判生死。

⚠️ 真正的上游問題換了位置：**兩個 unit 為什麼會走到同一格**。那是 target head 的
工作，還沒查。
