## §68 第二輪 CMA-ES：130 代收工，候選全面贏過 `cma1-g50-wt`

### 68.1 這一輪跑了什麼

```
temp/cma/20260901-174022
python -u -m tools.param_search --warm-start config/params/cma1-g50-wt.json \
    --seeds 40 --popsize 15 --generations 243 --checkpoint-every 10 --workers 10

40 維全搜（不是 --only 子空間）。跑 130 代放 STOP 收工，sigma 0.0254。
存檔完整，--resume temp/cma/20260901-174022 接得回去。
```

先開了 14 維聚焦那輪（`--only s65`），25 分鐘就停掉 —— 停的理由是**凍住 26 維
等於假設「那 26 維的最佳值不會因為那 14 維動了而跟著移」，而這件事沒有任何
測量支持**。詳見 §66.5。

🩸 **`train` 那一欄按定義單調遞增**（它是「歷來最佳」），而且是 1,800 個候選
裡挑最大的 —— 每個候選在 40 個 seed 上的分數對真實實力的估計 SE 約 4,092，
**挑最大值本身就會往上偏**。有資訊量的是 `holdout`（沒有選擇偏差）。

### 68.3 停下來的理由

不是「開始變差」（holdout 最後兩個 checkpoint 是歷來最高的兩個），是
**用 40 局判不動，再跑 14 小時還是用 40 局判不動**：

```
holdout 40 局    SE 4,092    ← 搜尋期間唯一的誠實數字
驗收 400 局      SE   567
```

sigma 也已經收到 0.0254，而 2026-08-25 量到 margin 在 sigma≈0.05 時要 54 個
seed 才排得動相鄰候選，我們只有 40 個。

### 68.5 gen1 那個零怎麼解釋

搜尋過程中 `gen1` 那一欄一直不漲（八支重播平均漲到 +11,810，gen1 十次量測
平均約 0），一度懷疑是**學到專打不會反應的重播**（`param_search.py` 的註解
就寫著這個風險）。

排開四種對手之後這個懷疑不成立：

```
對手              會反應   強度    候選比出貨版好多少
ladder-top-a        ✗      強      +15,449   t=+9.74
另外八支重播        ✗      強      +11,810   （checkpoint）
cma1-g50-wt         ✓      強       +6,731   t=+11.88   ← 關鍵
gen1                ✓      弱          ~0
```

**「會反應」那條軸有覆蓋了，候選照樣贏。** 剩下的解釋是 gen1 太弱：對它我們
已經賺到 100,106（比對誰都高），市場吃滿，再有效率也沒地方賣。

⚠️ **誠實剩下的限制**：會反應的證據**全部來自我們自己的程式碼血統**
（`cma1-g50-wt` 和 `gen1` 都是 gen0）。真人的 replay 一律不會反應，所以
「強 + 會反應 + 不是我們自己」這個組合量不到。而「贏過自己舊版」這把尺
騙過一次（本機對 gen1 100 勝 0 負、線上排 3000/5000）—— 但這次它不是唯一
證據，同一組參數對**八個不同真人的重播**也全面變好。
