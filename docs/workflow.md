# 流程

---

## 1. 訓練循環

```
【第 0 代】手寫規則式 AI（if-else + 貪婪排程）
      │
      │ 讓它自己跟自己打 5,000 局
      │ 每一步都記錄：當時局面 → 它做了什麼 → 這局最後贏/輸多少
      ▼
   訓練網路模仿它
      │  policy 學「它會做什麼」
      │  value 學「這局面最後結果如何」
      ▼
【第 1 代】網路 + beam search
      │  ⚡ 已經比第 0 代強
      │     因為搜尋會驗算網路的直覺
      │
      │ 用第 1 代打 5,000 局
      ▼
   重新訓練
      ▼
【第 2 代】→【第 3 代】→ ... →【第 5 代】
```

### 每一代的晉級條件

新的一代必須在評估天梯上**統計顯著地**打贏上一代，才能採用。

**打不贏就丟掉，用回舊的。** 這保證了每一代都不會退步——這是我們選這個方法的核心理由。

### 一代要跑多久（估）

| 步驟 | 時間 |
|---|---|
| 產 5,000 局棋譜 | 1~3 小時（取決於產線吞吐） |
| 訓練 | 20~40 分鐘（GPU） |
| 晉級判定 | 30~60 分鐘 |
| **一代合計** | **約半天** |

所以 Week 4~5 兩週跑 4 代是寬鬆的，有很多時間可以除錯和調整。

## 2. 六週排程

起算 2026-08-13；Entry / Team Merger 截止 2026-09-23，Final Submission 截止
2026-09-30。之後官方會繼續跑對局約兩週完成最終排名。

| 週次 | A 線（基建） | B 線（AI） | 里程碑 |
|---|---|---|---|
| **Day 1-3** | 讀原始碼、repo 骨架 | 讀原始碼、PyTorch 暖身 | 介面凍結、**Kaggle 組隊完成** |
| **W1** | 規則鏡像、編碼器 | 第 0 代 AI | |
| **W2** | **對戰產線** | **評估天梯** | 🎯 吞吐 > 5,000 局/小時 |
| **W3** | inference server、submission 打包 | 網路、訓練 pipeline | 🎯 **第一次提交** |
| **W4** | 吞吐調優、參數搜尋 | 第 2、3 代 | 🎯 有分數在榜上 |
| **W5** | 壓力測試 | 第 4 代、終盤策略 | 🎯 分數穩定爬升 |
| **W6** | 凍結、備援 submission | 挑最強的 checkpoint | 🎯 不要搞砸 |

### 三個不能移動的節點

**Day 3：Kaggle 組隊完成。**
組隊合併有獨立截止日，兩人都要先各自報名。跟技術無關但會讓專案歸零。

**W2 結束：對戰產線吞吐達標。**
不達標就停下來一起修，不要往前做。B 線沒有棋譜就是在空轉。

**W3 結束：第一次提交成功。**
用第 0 代笨 AI 就好。目的是把提交流程、時限、驗證機制全部走一遍。

## 3. 改動流程

```
改 code
   ↓
加 log（改哪裡就 log 哪裡的判斷依據）
   ↓
L0 smoke（< 60 秒）  ──失敗──▶ 修 code，不要放寬檢查
   ↓ 過
L1 quick（~5 分鐘）  ──明顯變爛──▶ 回頭想
   ↓ 沒變爛
繼續做別的 / 累積幾個改動
   ↓
L2 判定（整合日，30~60 分鐘）
   ↓ 確認變強
更新 baseline，記錄統計結果
```

三層測試的細節在 `rules.md` §2。

## 4. 比賽端硬限制

| 限制 | 對策 |
|---|---|
| 只有 CPU、submission ≤ 100 MiB | `main.py` 或以 `main.py` 為根的 tar.gz；模型存 `.npz`，numpy 手刻前向 |
| **不准 import torch** | 載入要好幾秒，第一回合就可能超時 |
| 每回合有時限 | anytime 搜尋：先產保底解，有時間才多想 |
| 引擎靜默拒絕非法動作 | 送出前必過 `legal_mask` |
| log 有長度上限 | submission 的 `LOG_LEVEL` 固定 0 |

## 5. 三個真正的失敗模式

按發生機率排序。**全部是軟體工程問題，不是 ML 問題。**

### 1️⃣ 對戰產線太慢（最常見）

產不出棋譜 → 訓練循環卡死 → 專案停擺。

**預防**：Week 2 就把吞吐當成唯一 KPI，達標才往下走。

### 2️⃣ Phase 0 沒把遊戲規則讀透

編碼器漏掉某個關鍵資訊 → **網路學不到它看不見的東西**。

而且這個問題**不會報錯**，只會表現成「怎麼訓練都不夠強」，最難查。

**預防**：兩人各讀一遍再對答案。

### 3️⃣ 最後一週才處理時限問題

上榜之後某幾局超時 → rating 被打下來。

**預防**：W3 第一次提交時就把 anytime 框架做完整。

## 6. 如果進度落後怎麼辦

按這個順序砍：

1. **砍代數** — 跑 3 代而不是 5 代。分數會低一點但不會歸零。
2. **砍搜尋深度** — beam width 調小，網路直覺為主。
3. **砍終盤策略（T62）** — 這是加分項不是必需品。
4. **❌ 絕對不能砍的**：evaluation 天梯、L0 smoke test、anytime 保底機制。

**砍掉評估能力等於瞎著開車。** 寧可少跑兩代，也不要在沒有判定機制的情況下亂改。
