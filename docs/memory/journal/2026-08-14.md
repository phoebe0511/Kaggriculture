## 犯過的錯（都值得記住）

1. **一次改多件事再看結果。** 市價估值那次同時改了買地順序和 `spendable`
   條件，量到退步就掛到最近改的東西上，結論完全相反。
2. **看到問題就猜原因。** 「12 個人為什麼輸」講了一整套現金流故事，沒驗證。
   使用者兩次指出來。
3. **拿當下的引擎狀態當永久事實**（`LAND_ORDER`）。
4. **debug print 被吃掉**。`kaggle_environments` 在呼叫 agent 時把 stdout/stderr
   導進 StringIO，`debug=False` 時整包丟掉。要從 agent 內部印東西只能寫檔。

## 現在卡在哪

**離排行榜的 8 萬還有距離（現在 ~$5.2 萬）。** 兩個已知的大坑還沒動：

1. **67% 的動作是走路。** 整季 7,189 個動作裡 MOVE 佔 4,853，
   真正生產的（WATER/HARVEST/PLANT/CARE/FEED）不到 25%，整季只收成 259 次。
   這是路徑規劃問題，`agents/gen0.py` 目前是「每個任務挑最近的閒置 unit」，
   沒有分區、沒有一趟做多件事。
2. **day 14~19 的種植空窗。** 75 格的農場六天只種 11 次 ——
   STRAWBERRY（17 天一輪）和 MELON（11 天）陸續被判定來不及，
   CARROT 還沒接手。田空著沒產出。

還有一個剛查到、還沒處理：

3. **買地被現金底線卡在 day 9。** `land_first_min_day: 3` 完全沒作用。
   實測（log 有記 `budget` 欄位，含 `floor` / `spendable` / `daily_ops`）：

   ```
   day 3  hr 0   cash $360    floor $891    spendable $0
   day 5  hr 0   cash $532    floor $945    spendable $0
   day 8  hr 0   cash $809    floor $981    spendable $0
   day 9  hr 8   cash $1,681  floor $1,574  spendable $107  ← 這時才買 NE
   ```

   `floor = daily_ops × cash_reserve_days(3)`，而 `daily_ops` 裡種子佔 36~39%
   （25 格的種子日耗 $117）。收入還沒起來時底線永遠高過現金，`spendable` 一直是 0。

   注意同一天 hour 0 和 hour 8 差很多（day 9 是 $1,004 → $1,681）——
   早上剛付完工資和種子，中午賣完貨才有錢。

   **三個可以動的地方（都還沒試）：**

   1. **買地不受現金底線限制** —— 底線的用途是「不要把日常運作的錢花掉」，
      但買地是一次性投資。改成用 `money` 而不是 `spendable` 判斷，
      只留一個小額保護（例如 `money - 地價 >= daily_ops × 1`）。**最直接。**
   2. **調低 `cash_reserve_days`** —— 但已經掃過，3 是單峰最佳點，
      1 和 2 都明顯較差，所以這條大概走不通。
   3. **接受 day 9** —— 也許現在的時機本來就是對的，沒證據說早買比較好。
      注意 day 0 買地已經實測是壞的（0 勝 20 負、差 $17,402）。
