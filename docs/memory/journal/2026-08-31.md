## §54 🔴 找到了：reward 對齊就是病因。§37 的決定是錯的

### 54.1 A/B 結果

兩組除 reward 外完全相同，`--seed 4242 --seed0 900000`。seeding 修好
（`528e692`）之後**第 0 輪的取樣現金完全相同（63,239）**，對照是乾淨的。

```
ab-zs         63,239      56,789        49,162        1.94    0.909
```

**own-cash 把策略毀掉，zero-sum 大致保住。** 符合 §52.6 預先寫死的第一條：
「ab-zs 不崩、ab-own 崩 -> reward 對齊是病因」。

### 54.2 §37 的理由被高估了

§37（08-28）把 reward 從零和改成只看自己，理由是對手項佔 86.4% 的變異數
「而且我們控制不了」。兩個前提都不成立：

- **「控制不了」是錯的** —— §49 的 sp100 量到：只改自己建物位置，
  對手現金動了 +11,158。
- **變異數的擔憂被高估** —— 第三條判讀標準（ev 掉到 0.5 以下）沒發生，
  ev 只從 0.983 掉到 0.909。value head 把多出來的變異數吸收掉了，
  而且 `contracts.py:516` 的 scalar 裡本來就有 `opp_money` / `money_ratio`。

§37 之後的**每一次 PPO 都用 own-cash**（warm3、ppo-hybrid、ppo-cma1-market、
ppo-scratch），也就是說 §48 / §50 / §52 觀察到的「越練越差」都可能是這個。

### 54.3 沒有解決的部分

zero-sum 不是萬靈丹：

高峰之後仍在下降，而且從沒回到起點附近（未訓練的 hybrid market

§52.3 的候選 2（取樣 vs greedy 分家）還沒排除。

## §55 🔴 兩件事：log 的 ev 量錯東西；ladder 頂端前 10 天不賺錢

### 55.1 ladder 頂端的現金曲線 —— 前 10 天是刻意不賺

用 `agents/replay.py` 重播 7 局真實 ladder 對局，**7 局的期末現金全部跟
Kaggle 原局相符**（`config/episodes/*.json` 的 `rewards`），所以曲線可信。

kawashigi（rating 3228.6）vs Thomas（3162.6），逐日期末現金：

```

 0          23   -2,977          23   -2,977       +0
 6       1,522   +1,218       1,539   +1,218      -17
 7           6   -1,516          23   -1,516      -17
```

第 0 天第一個回合就把 3,000 花到剩 22（99.3%），**九天現金都在 2,000 以下**。
8 支頂端隊伍一致：最低現金 2~66，現金回到 3,000 是 **步 257（第 10 天）**
（例外：tetsuya 步 168、ReCurSiON 步 240）。

我們的 `cma1-g50-wt` 打 kawashigi 重播（同一局 seed）：

```
天    kawashigi      我們       差值
 8       1,244      1,251        +7      <- 到這裡都一樣

```

**前 9 天我們跟頂端幾乎一樣，第 10 天他收穫了、我們沒有，之後 20 天沒追回來。**

reward 的含意：own-cash 下，第一個回合正確地把錢花光拿到
`(22-3000)/10000 = -0.298`，而整局勝負 ±1.0 折扣到期末只剩
`0.997^718 = 0.1156` —— **投資當下被扣的分是整場勝負訊號的 2.58 倍**。
零和下同一個動作是 **≈ 0**（兩個好玩家花錢時機一樣，相減抵銷），
這就是 §54 那 +26,612 的具體機制。

腳本：`scratchpad/cash_curve.py`、`cash_ours.py`、`reward_mass.py`。

### 55.2 🔴 `explained_variance` 量的是 GAE 回報，不是真實結果

`model/ppo.py:353` 的 `explained_variance()` 用的是 `self.ret`，而
`ret = adv + v` 是 lam=0.95 的 GAE 回報 —— **它本身大部分就是 v**。
所以那個數字有自我參照，會嚴重高估。

同一批 80 局（`ab-zs/best.pt` iter 59，seed0 7,000,000，參數照 checkpoint
存的 argv）：

```
ev(GAE lam=0.95 回報, v) = +0.866    <- train.jsonl 的 explained_var
ev(真 MC 回報,       v) = +0.242    <- 真的猜不猜得中結果
```

**§54.2 說「ev 只掉到 0.909，value head 把變異數吸收了」是建立在高估的數字上。
那個結論要收回** —— value head 其實只解釋了真實回報 24% 的變異數。
（§54.1 的 A/B 結論不受影響，那是比期末現金，不靠 ev。）

### 55.3 分段：value head 到處都不準，不是只有前段

```
區段                    sd(G)   sd(v)   corr      ev
步   0-240 (第 0-10天)   0.900   0.382  0.527   0.267
步 240-480 (第10-20天)   1.239   0.571  0.560   0.303
步 480-720 (第20-30天)   0.812   0.480  0.466   0.202
```

`sd(v)` 只有 `sd(G)` 的 42% —— **預測的散布遠小於真實**，一直往平均猜。

而且 **前 240 步的 G[t] 有 103% 來自第 240 步之後的 reward**（超過 100% 是
因為前段淨額為負）。也就是說第 0~10 天的價值**完全**由第 10 天以後決定，
value head 必須跨 240 步，而它只做到 ev 0.267。

### 55.4 lam 掃描：現在的訓練目標跟真實結果只有 0.61 相關

同一批 80 局，只換 `lam` 重算 GAE 回報：

```
lam       等效視窗    回報 sd    對真 MC corr
0.95        19 步     0.591        0.610      <- 現在
0.99        77 步     0.676        0.838
0.998      200 步     0.893        0.982
1.0        333 步     1.054        1.000
```

等效視窗 = `1/(1-gamma*lam)`。收穫在第 240 步，現在的視窗 19 步 ——
**差 12.6 倍，reward 這條路完全傳不回去，只能靠 ev 0.267 的 value head。**

`lam=0.998` 把目標跟真實的相關拉到 0.982，代價是回報 sd 從 0.591 到 0.893
（**1.51 倍**）。我先前口頭說的「變異數會大很多」是高估的，實測 1.5 倍。

腳本：`scratchpad/value_span2.py`。
