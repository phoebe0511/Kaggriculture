## 3. v3：把 unit 的「目標」變成顯式標籤

昨天的診斷是「老師的策略不是 observation 的函數 —— 這個 unit 要去哪不在任何欄位裡」。
今天把它變成標籤：一段連續 MOVE 加結尾那個非 MOVE 動作叫一個 **segment**，
segment 裡每一步的標籤是「終點在哪一格、到了做什麼」。

三個支持這個做法的實測（3 局 × 2 玩家、41,484 個 unit-turn）：

| | 數字 |
|---|---|
| MOVE 段落平均長度 | 1.79 步（56.4% 只有 1 步、99.4% ≤ 7 步） |
| **`gen0.step_toward` 重現老師實際那一步** | **93.02%**（18,372 / 19,750） |
| 走到一半就日終、沒有終點動作 | 4.2%（60 局全量是 3.6%），標成 -1 不算 loss |
| 段落終點動作 | WATER 34.2%、HARVEST 12.5%、PASS 12.5%、FEED 9.7%、COLLECT_FERTILIZER 9.6% |

第二列是關鍵：**路徑不用學。** `_step_toward` 改成公開的 `step_toward`。

### 訓練起來了，實戰仍然沒有


## 4. v4：市場也交給網路

昨天到今天早上市場一直沿用 `gen0._market`。量下去才知道那是致命的：

| | 老師（2 局平均） | gen0 的市場 |
|---|---|---|
| 整季賣出 | $185,358（1,553 個） | $9,977（90 個） |
| BUY_PRODUCT WHEAT（飼料） | 553 個 / $22,921 | 13 個 / $390 |
| BUY_ANIMAL | COW 10 + SHEEP 4 | COW 3 |
| 工資與買地 | $8,977 | $6,296 |

**花了對方 70% 的人事成本，產出 5%。**

### 🩸 兩個抽取上的坑

1. **同一回合同一個 op 會重複** —— 佔 9.6% 的 (回合, op) 組合。數量必須**相加**
   不是取後者：引擎逐單位重新報價，`SELL 5` + `SELL 5` 與 `SELL 10` 完全等價；
   `HIRE` 兩筆就是雇兩個人。
2. **`HIRE` 一次要送 n 筆。** 實測老師 **57.6% 的雇工回合一次送 5 筆**（最多 9 筆）
   —— hands 每天被清空，開工那一刻要一次補滿。第一版的 `decode_market` 只送 1 筆，
   等於每天上午都在慢慢補人。`clamp_market_qty` 用 fib 價格表算「還雇得起幾個」。

### 🩸 mask 的第一版擋掉老師 23.1% 的訂單

把「錢夠不夠」「shed 有沒有貨」寫進 `legal_market_mask`，結果 3,484 筆裡擋掉 804 筆
（`SELL FERTILIZER` 406、`SELL WHEAT` 234）。

因為**老師自己就會送出送不成的訂單** —— journal 08-19 §5 早就量過：整季送出約
1,460 筆 `FERTILIZER SELL`，實際只成交約 449 個。那是「有多少賣多少」的寫法。

照不變式該**放寬 mask**，不是調高門檻。那些條件搬到 `clamp_market_qty`，
`legal_market_mask` 現在只留「象限買完了不能再買地」一條。

### 結果：更差

## 5. `legal_unit_mask` 漏了五條，老師一次都沒犯過

`gen3_target` 送出的 852 次 `WATER` 裡，**501 次（58.8%）澆在今天已經澆過的格子上**
—— 引擎靜默 no-op。有效澆水只剩 351 次/局，老師是 928 次。作物連續兩天沒澆就變雜草。

老師的白費率（3 局 × 2 玩家、13,466 個動作）：

```
WATER 0.00%（5,569 筆）   FEED 0.00%（1,777）   CARE 0.00%（1,867）
COLLECT_FERTILIZER 0.00%（1,868）   HARVEST 0.08%（2,385 筆裡 2 筆）
```

所以這五條**可以加而不違反 mask 的不變式**。它們是漏掉，不是刻意留給網路學的。
補上之後白費動作 **9.2% → 0.0%**。這是今天唯一乾淨的一勝。

### 網路學不學得會這五條？學得到八成，但不夠

| | 老師的局面上 | 自己下場 | 倍率 |
|---|---|---|---|
| 全部白費動作 | 1.02% | 9.2% | 9× |
| WATER | 4.08% | 58.8% | **14×** |

規則本身是 AND 條件的硬規則（`kind == PLANT` **且** `not watered_today`），
五個 channel 全都在輸入裡。mask 一行就是 0%，網路永遠會有殘差，而殘差在閉迴路

### 6.1 老師不是在跑固定腳本（但開局是）

60 局全部是**不同的 seed**，カワシギ 出現在全部 60 局。它自己跨局的 unit 動作
一致率中位 **39.3%**（66 組兩兩比對，隨機基準約 10%）。所以資料的多樣性是真的。

**但開局前 73 步（3.0 天）逐字相同**，最長有一局到 426 步。719 個 step 裡，
farmer 動作在 12 局中完全相同的有 226 個（31.4%）。

⚠️ 「カワシギ vs Thomas 的跨隊一致率 45.1% 比自己跨局的 39.3% 還高」這個數字
**是被污染的** —— 12 局裡很多局兩人同場，同一個 seed、同一個市場，本來就會比較像。
不要拿它下結論。

## 7. ⚠️ 定死這件事的數字：開局腳本只跟得完 22%

拿**跟老師同一個 seed**（1220298539 / episode 93783010）跑，比對前 73 步：

```
區間              farmer 對        全部 unit 對
day 0（1~24）    10/24 =  42%     66/139 =  47%
day 1（25~48）    2/24 =   8%      2/24  =   8%
day 2（49~73）    4/25 =  16%      4/117 =   3%
整段腳本         16/73 =  22%     72/280 =  26%
```

盤面：

```
step        我們 作物/建物/動物/草  人   現金   |   老師 作物/建物/動物/草  人   現金
  24         11    4    3   0     0    498    |    19    4    4   0    0      23
  72          0    4    1  11     0    385    |    19    5    4   0    0      49
```

**day 2 結束時我們 0 作物、11 雜草，老師 19 作物、0 雜草。** 而且我們現金比老師多
—— 錢沒花出去。

### market head 在開局是對的

`gen4_market` 的 **step 1 市場訂單跟老師完全相同**（同一個集合）：
`HIRE ×5, BUY_ANIMAL COW 2, BUY_ANIMAL SHEEP 2, BUY_SEED WHEAT 7,
BUY_SEED MELON 12, BUY_PRODUCT WHEAT 6`。

`gen3_target`（走 gen0 的市場）第 1 步就錯（只買 1 隻 COW、每種種子各 1）。
**開局壞掉的是 unit 那一半，不是市場。**

### 為什麼是 22% —— 這是算得出來的

target 準確率 0.868，每一步有 13.2% 的機率走錯：

```
第一次走錯的期望步數    1 / 0.132 = 7.6 步
實測第一次分歧           第 6 步            ← 吻合
連續 73 步都對的機率     0.868^73 = 0.003%
要有一半機會跟完 73 步   0.5^(1/73) = 0.991
```

**一步走錯就永遠回不去腳本上。** 之後的盤面老師沒走過，比對本身就沒有意義了。

### 所以「抓更多 log」不是解

> 🔧 **2026-08-20 晚間更正 —— 這一段的範圍被寫得太寬了，見 §14.1。**
> 下面的論證只涵蓋 **v4 的逐 unit target head**，而且判定標準是「逐字重現老師
> 開局 73 步」這個代理目標。`0.868 ^ 73` 證明的是「跟不完腳本」，**不是**「打不好」
> —— 原文把兩件事綁在一起了。v5 換成逐格 demand 之後同一件事是 F1 0.9804，
> §6.3 那條曲線是在 v4 座標系上畫的，**對 v5 沒有效力，而且沒人在 v5 上重畫過**。
>
> 而且現在真正擋住老師 log 的不是這個算術，是工程缺口：
> `harness/build_dataset.py` 出現 `demand` 的次數是 **0**（實測 grep），
> 老師的 replay 產不出 v5 的標籤。**不要拿這一段當「不准再抓 log」的通則用。**

從 0.868 爬到 0.991，照 §6.3 的曲線（每倍增 +0.076 且在減速）需要**四次以上的倍增**
（60 → 960 局），而且準確率一定會在某處平掉 —— 老師有些決定本來就不是盤面的函數。
就算推到 0.95，`0.95^73` 還是 2%。

**抓弱 player 的 log 也不是解。** 他們的局面確實長得像我們（雜草多、動物少），
但他們在爛局面裡的動作是「一路爛下去」，不是「怎麼救回來」。而且 08-19 §7d 已經
量過混不同老師會更差。真要用的話唯一正確的用法是 rating-conditioned
（把 rating 當輸入欄位、推論時填最高值），但那沒有解決乘法問題。

> **要脫離這個乘法，只有兩條路：**
> 1. **降低需要連對的步數** —— 每一步都能自己修正，不依賴前一步對
> 2. **放棄模仿改用 search** —— 自己評估這一步好不好，不需要跟腳本
>
> 第 2 條就是 `workflow.md` §1 圖上原訂的路線，而 value head 已經訓出來了
> （RMSE 0.1474 vs dummy 0.2157）。缺的是 forward model。

## 8. 兩個新的 kill switch

08-19 §7d 的教訓是「準確率不是有效的 kill switch」。今天做了兩個替代品，
都不用標籤、一局就跑得出來（4 workers 約 1,400~1,600 局/小時）。

```bash
python -m eval.runner --a <版本> --b ladder-top-a --games 2 --workers 4
python -m tools.action_dist temp/<run 目錄>     # 動作分布
python -m tools.state_dist  temp/<run 目錄>     # 狀態分布，按天
```

| | 紅線 | gen2 | gen3(v4) | gen4 |
|---|---|---|---|---|
| `action_dist` | MOVE 差 ≤ 10pp、生產動作 ≥ 對方 10% | 5 條紅 | 2 條 | 2 條 |
| `state_dist` | 動物/作物/現金撐到 day 14 才掉出 p5 | — | 動物 day 1 | 動物 day 1 |

⚠️ **`state_dist` 那條紅線從來沒有綠過。** 每一版的動物都是 day 1 就掉出去。

## 11. Phase 3：DAgger 三輪，跑到 kill point

§7 的結論是「要脫離乘法，只有降低連對步數或改用 search」。當天稍晚把 DAgger
蓋起來跑了三輪 —— **它修掉了時間軸上的乘法，但撞到 unit 軸上的另一個乘法。**

### 兩個定案的決定

> **1. 提交端就是純網路，不做推論時搜尋。**
> 搜尋只在離線訓練時跑。推論時搜尋要呼叫引擎私有函式，而 `main.py` 底部已經
> 記過 1.29.3 與 1.32.7 的 `_commit_unit` 簽章不同、多傳一個參數的結果是
> **每一回合都 `TypeError`**，ladder 用哪個版本看不到。離線搜尋沒有這個風險，
> 也沒有 `actTimeout: 1` 秒的限制。
>
> **2. expert 做成可換的**，第一輪插 gen1 驗迴圈，之後換離線 search。

### 為什麼 gen1 可以當 expert

**DAgger 需要一個問得到答案的 expert。** 老師是 60 份固定 replay，問不到新局面
—— 這就是之前用不了 DAgger 的原因。gen1 問得到（每回合從當下盤面重算），而且
2026-08-20 量到它對老師是 **0 條紅線**（每條產線都在老師的 51~97%）。

⚠️ 代價是**天花板就是 gen1**（$73,150）。第一輪的價值在別處：驗證閉迴路修得掉，
以及產出 self-play 資料。

### 蓋的東西

| 檔案 | 做什麼 |

| `agents/gen0.task_destination()` | 從 `_task_action` 拆出來的「終點格 + 到了做什麼」。兩邊共用一份判斷，`_task_action` 只剩四行 |
| `agents/gen0.act(return_plan=True)` | 交出每個 unit 的 `(終點格, 終點動作)`。**那正好是 v3 的標籤格式** —— 我們自己的 agent 沒有理由像 replay 那樣從 MOVE 段落反推 |

### ⚠️ 乘法從時間軸搬到了 unit 軸

動作分布一直往 gen1 靠 —— 生產動作 32.5% 已經**超過** gen1 的 25.9% —— 但現金

```
0.63 ^ 12 = 0.4%          （對照 §7 的 0.868 ^ 73 = 0.003%）
```

同一個結構，只是從「連續 73 步都要對」變成「同一回合 12 個 unit 都要對」。

而且 target 有一部分**本質上學不起來**：`_minimum_cost_assignment` 是全域最小
成本配對，兩個 unit 離同一格一樣近時派誰去都對，而逐 unit 計較身分的 loss 在
那些情況下是在擬合雜訊。target 準確率隨著資料變多**反而下降**
（0.7580 → 0.6505 → 0.6301），符合這個解釋。

### 下一步（未動手）：網路預測「需求」，配對還給演算法

gen1 決定 unit 去哪是兩步：

```

步驟 2  把 12 個人配到這些工作，總距離最短        ← 配對，最佳化演算法，算得出最佳解
```

**現在網路把兩步一起做掉了。** 提議是只做步驟 1，步驟 2 還給
`_minimum_cost_assignment`（gen1 實測它對貪婪分派器 58 勝 2 負）。組合爆炸那一段
就完全不經過網路。

這跟 journal 08-19 §7e 的 option B 同方向，但當時沒有 target 準確率這個量測，
說不出「為什麼」。

### self-play 資料是這一輪唯一可以帶走的東西

value head 在 round 0 的資料上 RMSE **0.0803 對 dummy 0.2515**（3.1 倍），
而 replay 資料只有 0.1474 對 0.2157（1.5 倍）。而且組內變異數佔總變異數 48.6%
（同一個對手內部標準差 $14,925）—— 那份資料裡確實有「打得好不好」的訊號，
不只是「對手是誰」。**離線 search 需要的評估函式有著落了。**

| **v4** 逐 unit target | `weights-v4.npz` → **2,061 / 4,559** | `weights-dagger2` → **8,886** |
| **v5** 逐格 demand | **不存在** | `weights-v5-round1` → **88,483** |

**每次換 schema 都同時換了 expert，所以這是個 confound** —— v5 好很多有多少來自
切法對、有多少來自「模仿 gen1 比模仿老師簡單」，現在分不開。左下角那格是拆開它
的實驗，而且它的天花板是 **142,689 不是 92,860**。

擋住它的是 §7 更正框裡那件事：`harness/build_dataset.py` 沒有 `demand` 標籤。

### 14.2 「DAgger 的天花板是 gen1」不等於「這條路走不通」

`docs/CLAUDE.md` 的方法路線是 **Expert Iteration**：

> 規則式 AI 暖身 → 訓練網路 → 網路 + beam search → 再訓練，共 4~6 代。

**DAgger + gen1 expert 就是「訓練網路」那一步**，目的不是打贏 gen1，是產出
(a) 跑得快的 policy prior、(b) 有 value head 的網路，讓 search 有東西可以站。
§11 自己寫過「第一輪的價值在別處」。所以「重現 gen1 的 95.5%」是這一步**該有的
結果**，不是失敗。拿 118,146（ladder-top-a）去比 88,483 是把整條線的目標接到
單一步上，那個比較無效。

### 14.3 模仿率不該當往下一步的門檻 —— 這件事量過三次了

「模仿到幾成」其實是四個數字：

| | 數字 | 出處 |
|---|---|---|
| demand F1（teacher forcing，gen1 的盤面上） | 0.9804（dummy 0.3677） | §12 |
| 現金比 gen1 | 88,483 / 92,597 = **95.6%** | §13.1 |
| 配對勝率 | 8/40 = **20.0%** | §13.1 |
| **閉迴路動作一致率**（自己走、每回合問 gen1） | **沒有人量過** | — |

而拿準確率當門檻，跟已經量到的東西衝突：

```
08-19 §7d   每一步 94% 猜對          整局打不出來
08-20 §7    teacher forcing 0.9666   開局腳本只跟得完 22%
08-20 §11   op 0.9170 → 0.8681       現金 $0 → $14,745   ← 準確率降、實戰升
```

§11 已經標過這是「準確率不是 kill switch」的第三個獨立證據。**套上「模仿要 9 成」
這條規則會擋掉 round 1，而 round 1 是實戰變好的那一版。**

有效的閘門是 §8 那兩個 kill switch。v5 的 `action_dist` 對 ladder-top-a 是 0 條紅線，
但 **§8 那張表沒有 v5 的 `state_dist`** —— 「動物撐到 day 14」那條紅線從 gen2 到
gen4 從來沒綠過，v5 之後沒重量。

### 14.4 真正擋住 search 的是 forward model：全 repo 0 行

```
grep -rln "forward_model|beam|def search|rollout_policy" --include=*.py .
→ 0 行
```

`tools/` `eval/` `harness/` `serving/` 裡沒有任何 search 的東西。§7 自己寫的就是
「缺的是 forward model」。**所以「下一步」現在不是可不可以做，是一行都還沒蓋。**

不過比看起來便宜：§11 已經定案「搜尋只在離線訓練時跑，提交端純網路」，離線就
沒有「呼叫引擎私有函式 → 換版本每回合 `TypeError`」的風險，**forward model 可以
直接用引擎本身，不用學一個**。

### 14.5 gen0 被接回來的五項，性質不一樣

| 交還給 gen0 的 | 判斷 | 憑什麼 |
|---|---|---|
| 誰去哪一格（`_minimum_cost_assignment`） | **該** | 最佳化問題有最佳解；tie-break 的任意性會變成標籤雜訊（§11） |
| 走哪一步（`step_toward`） | **該** | 對 replay 命中 93.02%（§3）。剩下 7% 沒量過是什麼 |
| `FETCH_*` 幾趟 | 該 | 是 FEED / FERTILIZE / PLACE 格數的導出量 |
| `PLANT` 種什麼、`PLACE` 放哪種 | **沒有證據** | 說是「查表」，但 `dynamic_basket` / `_plan_animals` 是 200 多行的啟發式。沒人量過網路學不學得起來 |
| **整個市場**（269 行的 `_market`） | **沒解決，是關掉** | market head 召回率 0.72；處理方式是 `model_market: False`。§12 寫「下一個要處理的就是它」，然後去打包 submission 了 |

⚠️ 最後一項對 search 是硬傷：**search 搜的是 demand map，市場不在 demand map 裡。**

### 14.6 建議的順序

1. **老師的動作有多少落在 `TASK_OPS` 11 個 op 的表達範圍內**（半小時）。
   低的話 §14.1 那格不用做，而那本身是重要結論
2. **`build_dataset.py` 補 demand 標籤** → 填 §14.1 左下角那格。判定用「反推的
   demand 餵回 `_tasks(demand=...)` 之後、命中老師實際那一步的比例」，
   **要比 §3 的 93.02% 高**（demand 比 target 少一層資訊）
3. **市場**（召回率 0.72 是明確目標）
4. **`state_dist` 對 v5 補量一次**
5. **才是 search**
