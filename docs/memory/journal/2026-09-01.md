### 57.3 gamma=1.0：value head 修好了，成績沒動

`--gamma 1.0 --lam 0.998`，其餘照 `ab-lam`。**34 個 checkpoint 從來沒有
一支設過 `--gamma`**，全部吃預設 0.997。

動機（實算）：`0.997^240 = 0.486`、`0.997^718 = 0.116`。reward 是
`(da-db)/10000`，**不打折相加會 telescope 成期末現金差** —— 也就是真正的
目標。加 gamma=0.997 之後，「第 0 天花 1 塊、第 10 天收回 1.5 塊」在訓練
目標裡算成 `-1 + 1.5×0.486 = -0.27`，是虧的。**要回收 2.06 倍才不虧。**

結果：40 局差額 −24,849，跟未訓練的 −24,952 分不出來。

**但 value head 確實修好了**（§58.2 的真 MC 量測）：對實際終局結果的
解釋力 0.416，`ab-lam` 只有 0.064。**它學會判斷盤面了，成績還是沒動 ——
所以 credit assignment 不是瓶頸。**

### 57.4 🩸 best.pt 用現金挑，弄丟了最好的那一輪

## §61 🔴 PPO 看不到對手種什麼

`contracts.py` 的觀測編碼，關於對手只有：

```
格子層  opp_unlocked、opp_crop、opp_structure、opp_animal    ← 全是 0/1
全域    opp_money、opp_n_quadrants、opp_n_structures、
        opp_n_animals、opp_n_crop_tiles
```

**`opp_crop` 只有「這格有東西」，沒有品項、沒有 `planted_day`。**
對照它看自己的田：`crop_{c}`（哪一種）、`crop_age`、`crop_yield_frac`、
`crop_lifespan_left`。

所以 PPO **算不出收成日的價格**。價格是庫存的純函數（§59.2），要預測就得
知道未來的供給，而未來的供給主要來自「對手田裡種了什麼、種多久了」。
它看得到「對手有 12 格在種東西」，看不到「那是第 0 天種的哈密瓜，
會在步 284 一起收成把價格從 271 打到 76」。

**規則式的 `incoming_supply()` 直接讀原始觀測，拿得到品項和天數 ——
它在這件事上握有比 PPO 多的資訊。**

補的方法：加 `opp_crop_{c}`（5 個）+ `opp_crop_age` + `opp_crop_yield_frac`。
⚠️ 改編碼會讓現有 checkpoint 全部作廢（`encoder_version` 對不上），
要從監督式起點重來。但那五支的成績本來就是「最好的比不訓練好一點、勝率 0」，
沿用的價值不高。

順帶量到 PPO 實際下什麼單（10 局 greedy，每局開單次數）：


**它不是只會賣一樣，而且訓練確實在改變它**（賣哈密瓜 10.9→38.7、
賣牛奶 13.3→45.4）。但小麥它不賣、只買 —— 跟規則式一樣把小麥當飼料。
