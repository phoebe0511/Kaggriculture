### 86.2 原因：`if / elif` 撞上最後一天的任務過濾器

攔 `gen0._assign` 看到 step 700 之後傳進去的任務數是 **0**；再攔
`_tasks` 看過濾前的原始清單：

```
step 696~718 每一步   WATER 26   CARE 13   COLLECT_FERTILIZER 13   FEED 13
                      HARVEST 5, 5, 4, 3, 0, 0, 0 ...
```

`_tile_tasks` 的 PLANT 分支是 `if _needs_water(...) ... elif ripe ...`。
一格如果**既成熟又還沒澆水**，只生 WATER；而 `act()` 在最後一天把任務
過濾成只留 HARVEST（「WATER / CARE / FERTILIZE / DIG / PLANT 都不會增加
最終現金」）。兩件事單獨看都合理，湊在一起就是那一格整天沒人碰。

同一個過濾器也丟掉 `COLLECT_FERTILIZER`。FERTILIZER 是 `PRODUCTS` 之一，
撿進 shed 之後清倉期照賣（`_planned_sale_orders` 的 `forced`）。

### 86.3 修法：新參數 `final_day_harvest_all`，預設 False

⚠️ **不能直接改 code 的行為。** `config/opponents/*.json` 那些凍結對手
都是 `agents.gen0:act` + 一份 params；`frozen` 只擋 `DEFAULT_PARAMS` 漂移，
**擋不住 code 漂移**。直接改 `elif` 會讓 cma1-g50-wt / cma4-g134 / cma5-g175
當對手時全部變成另一支 agent，所有歷史比較同時位移。

所以：
```
DEFAULT_PARAMS["final_day_harvest_all"] = False     # 不改變行為的那一側
_tile_tasks   最後一天（days_left == 1）成熟的格子，即使同時要澆水也補一筆 HARVEST
act           最後一天的過濾器多留 COLLECT_FERTILIZER
tests/test_frozen_reference.py   加進 _ADDED_AFTER_REF_V11
tests/test_gen1_policy.py        +4 項（開關兩側、非最後一天不受影響）
```

🩸 **副作用**：`tools/freeze_params.py` 要求新 config 展開全部
`DEFAULT_PARAMS`。下一次凍結 CMA-ES 產出時，base params 來自 g175
（沒有這個 key），會噴「少了 1 個 key」。那時要**明確設成 True**。

### 86.6 最後一天順便澆水：試了，是負的

§86.5 原本推測「最後一天先澆再收」值得做。引擎的事實沒錯 —— 非持續型作物
在窗內澆水 `yield_units` 當場 +1（`kaggriculture.py:427`，不是 EOD），
day 29 開場平均有 19.5 格在窗內、全部收得下來，牌面 $968。

實作（`_water_adds_yield` 篩掉沒有加成的水，最後一天的過濾器多留 WATER）
之後量出來：

```
                    配對差平均     SE     手上卡住的    最後一天動作
只補 HARVEST          +1,216     161        $173     PASS 20% MOVE 57% DROP 100
＋最後一天澆水          +555     225      $1,667     PASS 10% MOVE 61% DROP  60
```

**原因**：`act()` 最後一天的「回倉庫卸貨」那段（2658 行）只對 idle 的 unit
生效。WATER 的優先序是 3、比 HARVEST 的 4 高，留著它就把 unit 全部排滿，
沒有人變 idle，收下來的 33.2 個單位一路握在手上到終局 —— 手上的東西期末
一毛不算。多長的 $968 補不回卡住的 $1,667。

已經 `git checkout` 退掉，`agents/gen0.py` 維持只補 HARVEST 的版本。
要拿到那 $968 得先讓「帶著貨的 unit 在當天結束前回倉庫」不依賴 idle，
那是另一個改動，沒做。

### 86.7 順帶量到的：平常日澆已可收的格子是對的

夥伴問「已經可以收成的格子還會再澆水嗎」。會，而且多數是對的 ——
非持續型作物 HARVEST 會把整格移除，所以正確打法是澆到 `yield_units`
累到 `max_yield` 再一次收。12 局分類（我方 unit-turn 77,913，WATER 10,347
佔 13.3%）：

```
窗外：只避免枯死                 292.1/局   33.9%   age 0~1 的新苗，必澆
窗內：當場 +1（而且已可收）        246.0/局   28.5%   已可收但還在長 -> 對的
持續型（EOD 產出）              229.7/局   26.6%
窗內：當場 +1                    73.0/局    8.5%
窗外：只避免枯死（而且已可收）       17.2/局    2.0%   <- 唯一白花的
無效（腳下不是作物）                4.2/局    0.5%
```

真正白花的是最後一類：已可收、又出了產出窗，澆下去只防枯死，而收成本來
就會讓那格消失，順便把收成延後一回合。17.2 個 unit-turn/局 = 全部
unit-turn 的 0.26%。不值得為它動 `if/elif` 的順序。
