# 2026-08-21：網路的加值是負的，改做端到端 prior + 離線 search

⚠️ **接手的人先看 §1。** 昨天的 v5（`gen4_demand`）不是「網路版」，它是
`gen0.py` 換一個包裝，而且**包得比原版差 4.4%**。今天把路線改掉了。

## 1. 定調的那個數字

```
40 局配對   gen4_rulemarket(v5 網路)  88,483   vs   gen1(純規則)  92,597
```

**網路的加值是負的。** v5 只讓網路輸出一張 `[11,100]` 的 bool（哪一格要做
什麼）；配對（`_minimum_cost_assignment`）、走路（`step_toward`）、`FETCH_*`
趟數、`PLANT` 種什麼、整個市場（`_market`，269 行）全部是 gen0 原封不動。

三代網路（v3 逐 unit target、v4 市場、v5 逐格 demand）全部是模仿，而
**模仿的天花板就是被模仿的對象**。

### 兩個框架上的更正（我昨天講錯的）

1. **「DAgger 天花板是 gen1」≠「這條路走不通」。** `docs/CLAUDE.md` 的路線是
   Expert Iteration：規則式 → 訓練網路 → 網路 + search → 再訓練。
   DAgger + gen1 expert **就是「訓練網路」那一步**，目的不是贏 gen1，是產出
   prior 和 value head 讓 search 有東西可站。「重現 gen1 的 95.5%」是這一步
   該有的結果。
2. **不能拿 88,483 當新架構的門檻** —— 那是 gen0 的成績，不是網路的。
   正確的基準是規則式自己（榜上 7 萬+、本機配對 92,860）。

## 2. 新路線：端到端 prior

**search 只搜得到網路輸出的東西。** v5 的 demand map 表達不了市場、表達不了
配對，所以 search 永遠碰不到那兩塊。prior 必須是完整動作空間：
44 個 `UNIT_OPS` + 21 個 `MARKET_OPS`。

驗收標準跟 v3/v4/v5 完全不同：

| 階段 | 看什麼 | 不看什麼 |
|---|---|---|
| 1. 模仿 | **top-k 涵蓋率**、value RMSE | argmax 準確率、勝率 |
| 2. search | search 對規則式的 40 局配對勝率 | 網路自己的準確率 |
| 3. 重訓 | 對規則式的配對勝率 | — |

search 要的是「正確答案在候選裡」，不是「第一名就對」。而這個 repo 已經量過
**三次**「準確率不預測實戰」（08-19 §7d、08-20 §7、08-20 §11）。

## 4. 合併 gen0 / gen1

`agents/gen1.py` 97 行 = 21 個 key 的 `DEFAULT_PARAMS` + `act()` 直接呼叫
`gen0_act`。它存在的理由寫在自己 docstring（「Gen0 保持為 ref-v2 的凍結量尺」），
而 ref-v2 的參數本來就寫在 JSON 裡 —— 理由不成立，歷史遺留。

### 🩸 差點踩到的坑：檢查方向搞反

第一次我檢查「哪些 **gen0** 的 key 沒被 config 展開」，得到 5 個，就下結論
「合併安全」。**該查的是哪些 gen1 的 key 沒被展開：**

```
ref-v2.json  FROZEN  params=27  ->  沒指定 gen1 的 19 個 key
ref-v1.json          params=24  ->  19 個
gen0 / 5 個 gen0-* / pq4        ->  20~21 個
```

那 19 個裡有 `optimal_assignment`（+$8,686、58 勝 2 負）、`tiles_per_unit`、
`water_on_demand`、`late_crew_caps`。**讓 gen1 的參數變成唯一預設 = ref-v2
從 Gen0 靜默變成 Gen1**，不會有任何錯誤訊息。

### 做法與驗證

- gen1 的 21 項併進 `gen0.DEFAULT_PARAMS`（`n_structures` 9→12，其餘 20 個是新增）
- `_resolve_params` 搬進 gen0，**保留 `.get` 語意不是 `.pop`** ——
  `test_frozen_full_params_replace_live_gen1_defaults` 直接斷言了回傳值裡
  還有 `_replace_defaults`；`act()` 負責 pop
- 刪 `agents/gen1.py`，19 個 config 的 `entry` 改指 `agents.gen0:act`
- **刪掉 Gen0 線的 9 個對手**（ref-v1、ref-v2、gen0、5 個 gen0-* 消融、pq4）
  —— 留著只會變成量尺靜默位移

三個獨立驗證：

1. `baselines.json` 的三個期末現金（135366 / 124283 / 86199）在合併後的
   `agents.gen0:act` 上**逐項不變**
2. 合併後的 `DEFAULT_PARAMS` 逐項等於 `ref-v11.json` 的 51 個 params
   （ref-v11 本來就是「gen0 + gen1 完整展開」，是現成的獨立基準）
3. 改 entry 前逐檔比對「拿掉 entry 之後的 JSON 是否相同」，19 個全部成立

`pytest` 81 passed（原 82，刪掉 `test_ref_v2_stays_frozen` 那條）。

### 兩條測試改成明寫參數

`test_ladder_wages_keep_land_crew_cap_through_final_day` 和
`test_animal_purchase_respects_committed_housing_capacity` 原本吃
`DEFAULT_PARAMS`，測的是 Gen0 那組值下的算術（前者被 `late_crew_caps` 壓到 8、
後者 `n_structures` 9→12 讓餘位從 0 變 3）。**斷言強度沒有放寬** ——

### ⚠️ 留著沒處理的洞

`docs/CLAUDE.md` 寫「凍結量尺 params **完整展開**，不指向 `DEFAULT_PARAMS`」

會讓所有凍結尺同時位移。這輪照「前期階段凍結量尺意義不大」的決定不處理。

### ⚠️ 仍然 0 勝 80 負，而且那不奇怪

### 實測門檻 -1.0：症狀改善、分數沒動（第五次「離線好、實戰沒跟上」）

