# 2026-08-27：離線 search 這條路結案 —— 它有一大半在賭 RNG

⚠️ **接手的人先看 §11（機制）和 §2（證據作廢）。** 兩件事：

1. 過去兩天引用的主要證據（「N/N 局 search 全贏」「Wilcoxon p」）是**同義反覆**。
2. search 的 `argmax(期末現金)` 有很大一部分在挑「哪個候選讓鎮上開出對我有利
   的店」—— 而那由 `_spawn_weeds` 燒掉幾次 `rng.random()` 決定，跟動作品質
   完全無關。**網路不可能學會那個。**

- **過夜批跑完了**（§1）：10 局、`--policy net`、`--hours 6,12,18,22`、631 分鐘，
  1,200 個決策點，10 個 npz 寫進 `data/search/dagger-round7/`。
- 🩸 **`gain = q(贏家) − q(base)` 恆 ≥ 0，是恆等式**（§2）。base 自己就在候選裡，
  取 max 不可能比成員小。而且相鄰項抵消之後 **Σgain == 期末現金 − 對照組現金**
  （10 局誤差全部是 0）。所以「20/20 全贏」「10/10 全贏」「Wilcoxon p=1.9e-06」
  **不管 search 選得好不好都會長那樣**，什麼都沒證明。
- **真正有內容的是「現金比」**（§3）：對手會跟著動，那個沒有結構保證。
  過夜批 9/10 局變好（seed0000 反而變差）。8/10 局**對手的現金也上升**，
  平均 +15,161 —— 這個遊戲不是零和的。
- **`base_illegal` 28.6%**（§4）：網路被 search 推離分佈之後，會開出買不起的
  市場單。四個 hour 平均分佈，不是某個時段的問題。
- **標籤學不起來，而且原因查清楚了**（§5~§7）：把 261 個「search 改掉動作」
  的決策點換一個延續重評兩次，**原始 `gain` 對「換延續還贏不贏」零相關**
  （Spearman r = −0.004 / +0.008），兩批在點的層級**統計獨立**（一致率 52.0%，
  互相獨立時就該是 52.4%）。argmax 挑的是走運的鏈，不是比較好的動作。
- 🔴 **找到擺盪的實體機制**（§11）：`_end_of_day` 的 rng 是每天固定播種的，
  但 `_spawn_weeds` **每一格空地燒掉一次 `rng.random()`**，之後才用剩下的
  狀態抽鎮上要開哪間店。**種一格就重抽一次店** —— 而店決定每天消耗哪些產品、
  進而決定市價。seed 7 實測：兩局的店完全不同，STRAWBERRY 價 +47.7%、
  MILK +52.3%，對手賣的量一個沒變、收入多 57,645。**10 局全部都抽到不同的店。**
- **兩條補救的路當天就量掉了**（§9/§10）：減掉對手上限 15%；value head 最好的
  情況誤差 16,140 元，是要取代的 4,572 的 3.5 倍。
- **建議回到參數搜尋**（CMA-ES 調 gen0 參數）—— 訊號在整季的尺度，
  需要 54~197 個 seed，是做得到的數量。

## 2. `gain ≥ 0` 是恆等式，不是量測結果

`search/rollout_search.py:114-118` 強制基準線一定在候選裡（不在就拋
`ValueError`，那就是 08-26 seed 4 崩潰的原因）。既然：

```
gain_t = max_i q(候選_i) − q(base)      而 base 是候選之一
```

那 `gain_t ≥ 0` 就是「一堆數字取 max 不會小於其中任何一個」。**實測 1,200 個
決策點，最小 gain = 0，負的 0 個。**

### 而且會 telescoping

`q_t`（套贏家動作、之後用 net policy 打到底）**就等於**下一個決策點的
`q_base_{t+1}`（從 `s_{t+1}` 用 net policy 打到底）—— 兩者是同一條軌跡。所以

```
Σ_t gain_t = Σ_t (q_base_{t+1} − q_base_t) = 期末現金 − 對照組現金
```

實測（`temp/search-game-20260826-233232`）：

```
seed      對手         Σgain     實際差    誤差
seed0000  hire-0      29,499    29,499      0
seed0001  hire-2      50,004    50,004      0
seed0002  hire-4      82,984    82,984      0
seed0003  hire-8      49,323    49,323      0
seed0004  kawashigi   49,331    49,331      0
seed0005  tetsuya    102,600   102,600      0
seed0006  utkarsh     20,088    20,088      0
seed0007  recursion   50,265    50,265      0
seed0008  thomas      61,866    61,866      0
seed0009  peikopon    37,066    37,066      0
```

10 局全部誤差 0。

### 08-26 那批（gen0 走盤面）也一樣

那批的 progress 沒記 `gain` 欄位，改用等價的性質驗：因為 `q_t = q_base_{t+1}
≤ q_{t+1}`，**一局裡 `q` 的序列必須不遞減**。

```
                          相鄰 q 下降幾次    最後一個 q == 期末現金
gen0 批 (164624, 20 局)      0 / 580              20/20
net  批 (233232, 10 局)      0 / 1190             10/10
```

所以 **08-26 §5 的「20/20 局 search 都贏純 gen0、+25,871、p=1.9e-06」也是恆等式。**

### 這件事的範圍

- ❌ 不算數：`search_game` 印的 `cash_a` vs `cash_b` 配對檢定、勝場數、p 值、MDE
- ✅ 仍然算數：**現金比**（見 §3）、以及「蒸餾學不學得起來」那一整串（08-26
  §7/§8）—— 那些從來沒依賴 `gain` 的符號

## 5. 真正該問的問題：winner's curse

`gain` 大不代表那個動作好。51 個候選就算好壞完全一樣，30 天的連鎖反應也會讓
期末現金散開幾百到幾千塊；取 max 就是挑「這一局最走運的那條鏈」。

那種 gain **是真的錢**（rollout 決定性，我們真的走上那條鏈），但**不是可以蒸餾
的知識** —— 換一個延續，優勢就不見了。這跟 08-26 §7/§8 兩次蒸餾失敗、
data-scaling 曲線是平的完全吻合。

### `tools/search_curse_probe.py`（今天新增）

重播 progress 裡記的動作回到每個決策點，在 `gain > 0` 的點上把**贏家**和 **base**
各自套下去、用**另一個延續策略**打到底比大小。

```
勝率明顯 > 50%  -> 動作真的比較好，標籤有內容 -> 問題在混訓比例，去做加權
勝率 ≈ 50%      -> winner's curse -> 加資料/加權都沒用，要改 search 的形狀
```

**自我檢查先過了**（`--continuation net`，延續策略不換）：

```
temp/curse-net-20260827-110652    seed 4 / 8
delta == gain_orig   12/12 逐位元組相同
```

重播確實回到同一個狀態，所以換延續的結果可信。

## 6. 結果：原始 `gain` 對「動作好不好」零預測力

```
python -m tools.search_curse_probe temp/search-game-20260826-233232 \
    --continuation gen0 --workers 10
產物 temp/curse-gen0-20260827-110830      2.0 分鐘   261 個探測點
```

```
贏 114   平 76   輸 71        勝率 61.6%   binomial p = 0.0019
delta 中位數 0    平均 −35 ± 555（95%）    Wilcoxon p = 0.067
```

**符號有一點訊號，量完全沒有。** 贏得比較頻繁但贏很小（贏的中位 +434），
輸得比較少但輸很大（輸的中位 −1,218），淨值 ≈ 0。

決定性的兩個數字：

```
原始 gain 總和    533,026
換延續後總和       −9,188        -> 存活 −1.7%

原始 gain vs delta   Spearman r = −0.004  p = 0.947
                     Pearson  r = −0.035  p = 0.572
```

**零相關。** 原本測到的 `gain` 有多大，對「換一個延續還贏不贏」沒有任何預測力。
分桶也是同一件事，而且順序是反的：

```
原始 gain          n     勝率    delta 中位   delta 平均
0 ~ 500          151   66.1%          0        −49
500 ~ 2,000       66   56.0%          0       −528
2,000 ~ 10,000    32   50.0%          0       +725
10,000+           12   60.0%       +214       +820
```

`delta` 的尾巴很重（第 5% = −8,566、第 95% = +5,939、最小 −23,551、
最大 +27,727），中間 50% 幾乎貼在 0（第 25% = −4、第 75% = +237），
29.1% 完全平手。

### 這代表什麼

**`gain` 量到的是「這一局走運的鏈」，不是「這個動作比較好」。** 51 個候選好壞
差不多，30 天的連鎖反應把它們的期末現金散開，取 max 就挑到最走運的那條。
那筆錢是真的（rollout 決定性，我們真的走上去），但**換一個延續就蒸發**，
所以它不是網路學得起來的東西。

這解釋了 08-26 §7/§8 為什麼兩條路都失敗：不是稀釋比例的問題，也不是樣本數的
問題 —— **標籤本身沒有可推廣的內容**。加權、加資料、換編碼都改變不了這件事。

## 7. 對照組排除混淆：不是「gen0 不接手贏家鋪的路」

§6 有一個混淆：gen0 是另一套策略，本來就不會延續贏家的計畫。所以再測一次
**我方延續完全不變（還是 round6），只把重評 rollout 的對手換掉**。

```
python -m tools.search_curse_probe temp/search-game-20260826-233232 \
    --continuation net --rollout-opponent gen1 --workers 10
產物 temp/curse-net-vs-gen1-20260827-111235      7.3 分鐘   261 個探測點
```

🩸 `gen1` 在這個 repo 裡**不是另一支 agent**。`agents/gen1.py` 不存在；
`config/opponents/gen1.json` 是 `agents.gen0:act` 而且沒有 `params`，所以
`eval/runner.py:135-136` 回傳裸的 `gen0.act`，跑 `DEFAULT_PARAMS`
（`max_hands=12`）。而 seed 0~3 的對手 `hire-0/2/4/8` 也是同一支函式、
只改 `max_hands`。**所以 10 局裡只有 6 局（replay 那幾支）是真的換對手，
4 局只是換參數。** 這個方向對結論是保守的 —— 換得越小，優勢應該保留越多。

### 兩批的結果幾乎一模一樣

```
                       勝率      delta 平均     gain 存活率   gain vs delta
A 換我方延續(gen0)     61.6%        −35          −1.7%     Spearman r=−0.004 p=0.95
B 換對手(gen1)         60.6%        −32          −1.6%     Spearman r=+0.008 p=0.90
```

勝率都 ~61%（binomial p < 0.001），但**平均值都是 0**，**原始 gain 的存活率
都是 −2%**，**原始 gain 對 delta 的相關都是 0**。

### 決定性的一步：兩批對「同一個決策點」意見一致嗎

```
兩批都非平手的點 n=179
  符號一致 93/179 = 52.0%
  A 正比例 60.9%   B 正比例 60.9%
  若兩批互相獨立，一致率會是 52.4%      <- 實測 52.0%，完全吻合

  delta_A vs delta_B   Spearman r=−0.093 p=0.135
                       Pearson  r=+0.047 p=0.446
```

**兩批在點的層級上是統計獨立的。** A 說「這個點的贏家比較好」，B 有一半機會
說相反 —— 而且那正好是純粹靠各自 61% 基礎率該有的一致率。

所以那個 ~61% **不是「61% 的點有訊號」**，而是**類別層級的系統性偏差**：
search 挑的候選整體上偏向「馬上多拿一點現金」，那種小便宜換什麼延續都留得住。
但它**分不出哪一個個別決策是好的** —— 而蒸餾需要的正是後者。

分桶也印證：`gain` 最小的那一桶勝率最高（0~500 是 66%，10k+ 是 60%/45%），
順序跟「gain 大 = 動作好」相反。小 gain 那桶 94/151 是單一 unit 的小改動。

### 雜訊的絕對尺度

```
「換一個延續，同一對動作的期末現金差」的 sd
  A 同對手、換我方延續    4,572
  B 同延續、換對手       18,140

要把真實差距從雜訊裡分出來需要幾次 rollout（2.8·sd/訊號 的平方）
  訊號 =   100 元      A  16,390 次      B  257,980 次
  訊號 =   500 元      A     656 次      B   10,319 次
  訊號 = 2,000 元      A      41 次      B      645 次

現在用的是 1 次。而典型的動作差距是幾百元（原始 gain 中位 288）。
```

**差 2~4 個數量級。不是「多跑幾次取平均」救得回來的。**

## 8. 結論與下一步

**離線 rollout search 當作蒸餾的標籤來源，這條路以目前的形狀是死的。**
不是資料量不夠、不是混訓比例不對、不是編碼器看不見 —— 是
**30 天 horizon 的混沌把「這一步好不好」的訊號整個蓋掉了**，argmax 選的是
走運的鏈。

搜出來的錢是真的（現金比 9/10 變好、對真實頂端玩家 11/12 變好），
但那是**不可轉移**的。

### 沒被否定的東西

- search 本身在對局裡有效（只是產不出可學的標籤）
- 08-26 §13 的「補 `unit_target`」想法還沒測，但它解決的是另一個問題

08-25 建好）：CMA-ES 調 gen0 的參數。它的訊號在**整季**的尺度（配對差 sd
15,435~25,880），需要 54~197 個 seed —— 貴，但是**做得到的數量**。
而 search 這條路需要 656 個延續才分得出一步的好壞，差兩個數量級。

## 9. 「減掉對手」救不了（control variate 的上限）

market 是兩家共用的，所以 550 回合岔開之後有一部分變化是共同的。把目標從
`我方期末現金` 換成 `我方 − 對手`，理論上可以抵消掉那一塊。

實測（`tools/search_margin_probe.py`，吃 curse probe 的輸出，n=261）：

```
目標 = 我方期末現金      sd 4,572      要偵測 500 元需要   656 個延續
目標 = 我方 − 對手       sd 5,631      要偵測 500 元需要   995 個延續   ← 更糟

對手 delta 的 sd 6,520（我方是 4,572）
我方 delta vs 對手 delta   Pearson r = +0.532   Spearman r = +0.256
```

**相減是放大不是抵消**，因為 `Var(X − Y) = σx² + σy² − 2ρσxσy`，而對手抖得比
我方兇（σy > 2ρσx）。

用最佳係數也到頂：β = ρσx/σy = 0.373，`Var(X − βY) = σx²(1 − ρ²)`，
sd 最好只能降到 3,872（**0.85 倍**），需要的延續數 656 → 469。
**要靠 control variate 解決，|r| 得非常接近 1，現在是 0.53。**

兩個附帶發現：

1. **改我方一個動作，對手期末現金的擺盪比我方自己還大**（6,520 vs 4,572）。
2. margin 的平均是 **+514 ± 683（95%）、t 檢定 p = 0.141** —— 方向跟現金版
   （−35）不同，但**不顯著**，不能當成「換 margin 當目標比較好」的證據。

🩸 順帶：`search` 已經有**完美的對手模型**（rollout 裡的 `act_them` 就是真正
那一支），編碼器也看得到對手（`contracts.py:498-501` 四張空間圖、
`:516-531` 的 `opp_money` / `money_ratio` / `opp_n_*`）。所以問題從來不是
「沒有對手資訊」，是**拿來比大小的那個數字把它丟掉了** —— 而補回去也沒用。

### 還沒試、而且真的能砍變異的兩條

| | 機制 | 代價 |
|---|---|---|
| 縮短 horizon | 只 rollout K 天，剩下用 value head 估。延續能把結果帶偏的空間從 550 回合縮到 72 回合 | value head 的估計誤差；解析度要能分辨 0.3% |
| open-loop 延續 | 錄下 base 之後的動作序列，每個候選都重播**同一串**。候選之間不會因為 policy 重新反應而岔開 | **有系統性偏差**：需要後續配合的動作（買種子要種、雇人要派工）會被低估，而 search 已經偏向「馬上見效」的候選 |

兩條都是拿偏差換變異，都要另外驗偏差多大。

## 10. value head 也不夠準（縮短 horizon 這條路的判準）

`tools/value_head_probe.py`。**真值不能用 `board_reward`** —— 那是「一路搜到
底」的期末現金，而 value head 被訓練成猜「這個 policy 從這裡打下去會拿多少」。
用前者當真值會量到一個 −45,018 的假偏差（踩過一次）。正確的真值是 progress
裡的 `q_base`，而且**每個決策點各一個**（`board_reward` 是一局共用一個）。

```
python -m tools.value_head_probe data/search/dagger-round7     --run temp/search-game-20260826-233232

真值（q_base）平均 117,186   sd 19,808
預測          平均  80,573   sd 19,706
殘差 sd 19,674   偏差 −36,613
對照「永遠猜平均」 sd 19,808   ->  解釋掉的變異只有 1.4%
排序 Spearman r = +0.518
```

**但更直接的數字在 round6 自己的訓練 log 裡**
（`model/artifacts/ckpt-e2e-round6/train.log` 最後一行）：

```
[prior] ... value RMSE 0.1614 (dummy 0.3894)
```

`board_reward` 的單位是「期末現金 ÷ 100,000」，所以在**它自己的驗證集**上：

```
value head   RMSE 16,140 元      永遠猜平均 38,940 元   -> 解釋掉 82.8%
```

它不是壞掉 —— 在自己的地盤上有學到東西。我們的 search 盤面只解釋 1.4%，
是分佈偏移 + 我們的盤面散佈本來就窄（sd 19,808 vs 訓練集的 38,940）。

**但無論如何都不夠：**

```
value head 最好的情況（自己的驗證集）   RMSE 16,140 元
要取代的跨延續變異                       sd  4,572 元
                                        ->  3.5 倍
```

誤差有結構，相減會抵消一部分 —— 相鄰決策點的殘差相關 r = +0.869，相減之後
sd 從 19,674 降到 **9,975**。仍然是 4,572 的 2.2 倍。

```
殘差 sd（全部）        19,674
  局間的成分           12,269
  局內的成分           15,858
相鄰決策點殘差相關     r = +0.869
相減之後               9,975
```

⚠️ 「相鄰決策點」（差 6 小時）是**偏悲觀的代理** —— search 實際比較的兩個盤面
比那更像，真實數字會落在 9,975 以下。但要壓到 4,572 以下需要相關 r > 0.973。

## 11. 🔴 找到擺盪的實體機制：`_spawn_weeds` 的 RNG 消耗次數決定鎮上開哪間店

前面一直用「30 天的連鎖反應」這種說法帶過。今天把它挖出來了，而且是
**純運氣、跟動作品質完全無關**的通道。

### 引擎裡的三行

```
kaggriculture.py:871   rng = random.Random((seed * 1_000_003) ^ day)
                       每天重新播種 —— 固定，不受動作影響

:877                   _spawn_weeds(farm, board_size, weed_chance, rng)
                       ⚠️ 兩個 player 各呼叫一次，共用同一個 rng
:836-839               for y, x: if tiles[y][x] is None and rng.random() < 0.005
                       ⚠️ **每一格空地燒掉一次 rng.random()**

:891                   town["unlocked_shops"].append(rng.choice(sorted(SHOPS)))
                       ← 用**剩下的** rng 狀態抽
```

**空地數改變 → rng 燒掉的次數改變 → 抽到不同的店。**
種一格、收一格、蓋一個建築都會改到空地數。

### 店決定價格，價格是雙方共用的

### 範圍

- **10 局全部**都抽到不同的店（跑了 seed 0~9）。
- 對手期末現金的變化**幾乎完全來自賣出收入**（10 局總計賣出多 +154,798、
  期末現金多 +151,611），不是少花錢。

### 這件事解釋了什麼

| 先前的觀察 | 現在的解釋 |
|---|---|
| 8/10 局對手也變有錢（§3） | 它賣的量沒變，是價格被店的組合推高了 |
| 跨延續變異 sd 4,572、跟動作品質零相關（§6/§7） | 換延續 -> 空地數的軌跡不同 -> 抽到不同的店 -> 幾萬塊的收入洗牌 |
| 兩批 curse probe 在點的層級統計獨立（§7） | 兩批的店序列各自獨立地被打亂 |
| 減掉對手沒用（§9） | 店的效果對雙方**同向**，相減抵消不掉多少（r 只有 0.53，因為兩家賣的品項組合不同） |

**`argmax(期末現金)` 有很大一部分是在挑「哪個候選讓鎮上開出對我最有利的店」。**
那跟「這一步下得好不好」完全無關，而且學不起來 —— 網路看不到未來的 RNG。

🩸 反過來說，這個機制是**可控的**（空地數自己說了算，而且 rng 種子只跟
seed 和 day 有關）。要不要把它當成一條策略來用是另一個題目，今天沒做。
