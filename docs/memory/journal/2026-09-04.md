### 83.3 reward 改成「總資產變化」

現在的 reward 是每一步的現金變化。問題不是它有偏誤（gamma=1.0 時
不打折加總剛好等於期末現金差），而是**它在單步上是反向的**：
買種子、雇人、買地、買動物，每一個正確的投資在當下都記成扣分，
要等十天賣掉才回來。這就是為什麼 `lam` 非得開到 0.998。

改成：

```
r_t = Δ(我方總資產) − Δ(對手現金)
```

展開就是 `[Δ我方現金 − Δ對手現金] + ΔΦ我`，Φ = 非現金資產。
基礎維持零和（現金兩邊都看得到），shaping 只算自己（對手的倉庫、
手上、種子看不到，但 potential-based shaping 對任何自己狀態的函數
都保證最優策略不變）。整局加總 = 期末 margin。

**Φ 的入帳規則（用會計科目對）：**

```
科目                            基礎
現金                            面額
原料（種子存量）                 成本（CROPS[c]["seed"]），來不及種的減記 0
在製品（田裡尚未可收）            成本（種子價），來不及收成的減記 0
製成品（yield_units、倉庫、手上）  淨變現價值（沿價格曲線積分，不是牌價）
生物資產（動物）                 買價 × 剩餘天數比例
固定資產（土地）                 買價 × 剩餘天數比例
建物                            0（引擎蓋起來不收錢）
人手                            0（每晚解雇，工資是費用）
空地                            min(空地數, 剩餘產能) × 種子均價（選擇權價值）
```

土地按剩餘天數折舊解決了「會不會就不買地」：第 5 天買 1,000 的地記
`1000×24/29 = 827`（幾乎中性），第 25 天買記 138（重罰）。而且季末自動
歸零，**potential-based shaping 需要的終端條件自動滿足**，不用人工修正。

### 83.7 工程量比想像小：介面已經存在

`model/ppo.py` 的 `step_rewards()` 已經收一個逐步陣列做 shaping：

```python
if plant_weight and plants_a is not None:
    phi = pa * plant_weight
    r = r + gamma * phi[1:] - phi[:-1]      # potential-based shaping
```

`plants_a` 現在裝「作物格數」。**換成「總資產」的逐步序列就好** ——
同一個形狀、同一條公式。要動的是：

```
1. rollout 每一步多算一個總資產（現在算的是作物格數）
2. plant_weight 改成 1.0（資產本來就是錢的單位；phi 要先除 REWARD_SCALE）
```
