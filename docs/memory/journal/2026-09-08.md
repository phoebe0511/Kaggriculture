## §101 PPO 實作稽核：訓練 ≠ 上場 那一整族解釋被排除

`tools/ppo_audit.py`。**乾淨的部分（全部實測）**：

```

最後一步 adv = r_T - V(s_T)   差 0.00e+00（bootstrap=0 生效）
ret == adv + old_value        max 0.000e+00

  rollout greedy == ppo_agent greedy（units 與 market 都相同）、
  送出的動作 encode_unit_action 認不得的 0 個

```

**找到的六個疑點**（只 audit，沒改）：

1. **unit 的 qty head 在 PPO 這條路上是死的**。`decode_unit(op, None)` →
   qty 固定 1（`contracts.py:1088`），rollout 和 `ppo_agent` 都傳 None，
   `evaluate_actions` 不用 qty head。實測一次完整 update 後 `qty_out` 的
   grad 與參數變動都是 **0.000e+00**（`demand_out` 也是）。老師
   （`data/dagger/cma1-round4`，80,535 個 unit 決策）PICKUP 平均搬 **6.86**
   個、中位 9，只有 17.8% 是 1。跟 §94 的 PICKUP 4.49 倍同向。
2. **op head 有 56.58% 的 argmax 這一步不進引擎**，但照樣進 joint logprob。
3. **target_kl 管的是 joint action**，因子數隨雇了幾個人變動（§102 驗過，
   結果不支持這條）。
4. **worker 在 CPU rollout、主行程在 CUDA update**：同一份權重同一個動作，
   max |Δlogp| 6.908e-02、ratio 0.9333~1.0399、12.63% 的步 |ratio-1|>0.01。
   沒碰到 0.2 的 clip 邊界。
5. **value warmup 期間 `clip_grad_norm_` 的分母含 trunk 的（不會被套用的）
   梯度**（`ppo.py:594` 只清傳進去的 optimizer、`ppo.py:596` 算全部參數）。
   實測 clip 前 trunk grad 58.1，clip 後殘留 0.20（0.3%），**沒有累積失控、
   沒有髒的 step**。影響只有 warmup 的 log 和 value head 的步被縮小。
6. **PLANT 的跨 unit 原子規則**（引擎 `kaggriculture.py:920-931`：某作物需求
   超過種子數就整批作廢）。實測 4 局 greedy：我們 438 個 PLANT 作廢 6 個
   （1.37%），`cma5-g175` 在同一批盤面 452 個作廢 0 個。

沒涵蓋：引擎會不會靜默忽略我們送出的「合法」動作（只驗到
`encode_unit_action` 認得，沒送進引擎比對狀態變化）。

沿 production path 走（`argmax → step_toward → 引擎動作`，用 §98 那支驗過的

```

## §104 Greedy Conversion：一半以上的更新結構上改不了 greedy

driver 換成 **舊** checkpoint（ckpt-140），狀態與取樣動作都來自舊 policy。

```
                              op head      target head
取樣到的動作就是舊 argmax        94.78%        75.97%
aligned（Δlogp 與 adv 同號）     35.29%        48.81%

aligned 拆三塊              n / 佔aligned / 佔移動量
  greedy-visible        op 1,444 / 3.79% / 29.42%   tgt 4,400 / 8.34% / 19.65%
  greedy-hidden         op 16,276 / 42.69% / 8.41%  tgt 18,994 / 36.02% / 9.61%
  greedy 無關            op 20,402 / 53.52% / 14.66% tgt 29,340 / 55.64% / 22.31%
```

「greedy 無關」= 強化 greedy 本來就會選的動作（op 49.10%）+ 壓低 greedy 本來
就不會選的動作（op 4.42%、target 16.70%）。**這兩種都改變不了 greedy，卻都會
改善取樣分數** —— 這就是 sampling improvement 不轉成 greedy improvement 的直接
機制，跟「取樣側 12,758 的進步有 71.6% 是取樣分布往自己的 greedy 收斂」對得上。

op 15,567 個（gap 0.9141，60 輪降 0.0255）、target 15,788 個（gap 0.7928，
降 0.0501）。

⚠️ 這裡的 advantage 是**這次 rollout 現場算的**，ckpt-200 是用另外 60 批訓的，
所以「一致率」只能讀成「學到的東西 generalize 到新狀態時還看不看得出方向」。

```

它們的 logprob 確實被排除在 ratio / policy loss / approx_kl 之外（sanity 驗過），
但「不在 loss 裡」不等於「不會動」—— op head 是共用權重，軀幹被 target /
market / 有執行的 op / value loss 推動時它們跟著漂，而且現在沒有任何梯度項在
約束它。被釋放的預算也**沒有轉給有執行的 op**（每因子 KL 0.01994 vs 0.02005）。
`approx_kl` 因為只算被納入的因子而略降，總移動量反而增加 5.8%。

**判定 C：F2 不是實質問題。** 不是 A（greedy 沒改善，也沒突破 -32k）；不是 B
（B 要求 op learning signal 改善，但有執行的 op 每因子移動量一模一樣、取樣差額
一樣）。F2 在會計上是真的（佔 baseline 全部 movement 的 13.38%），拿掉也生效了，
但量不到任何下游改善。

限制：單一一對 run（run-to-run 噪音見 105.3）；60 輪都在 plateau 內（兩臂
greedy 斜率都是負的）；只驗了「排除在 policy loss 外」這一種切法。
