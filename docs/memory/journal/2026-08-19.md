## 5. 方法論陷阱：送出的訂單 ≠ 成交量

第一次掃 replay 的 `action["market"]` 時，看到頂端玩家 day 15 送出
**259 筆 FERTILIZER SELL**，day 21 送 164 筆、day 25 送 172 筆，整季送出約

**是假的。** 交叉驗證 `market.inventory`：FERTILIZER 整季只從 10,000 升到
10,449，也就是雙方合計只成交約 449 個。那些是「有多少賣多少」的訂單，
絕大部分因為 shed 沒貨而中止（`engine-notes.md` §6：錢不夠／shed 滿了 →
該筆訂單中止）。

`tools/revenue.py` 的 docstring 早就寫了這件事。**任何從 `action` 數量推出來
的結論都要用 `market.inventory` 交叉驗證。**

## 7b. ⚠️ 未解：L0 有 6 個測試在 `autocrlf=true` 的機器上必紅

`tests/test_frozen_reference.py` 的 `_sha256()` 直接 hash 檔案原始位元組，
但**期望值是 LF 版的 SHA**（也就是 git 實際存的內容）。

```
git config core.autocrlf                              true
工作目錄 config/opponents/ref-v7.json   2100 bytes，70 個 CRLF
git blob 同一個檔                        2030 bytes，0 個 CRLF

sha(工作目錄位元組)  cfdfc4215d8bc43ba247c65458b796b9435b32c3a1309405b0dbe5731bac566f
sha(LF 正規化後)     25e83d0142559a87faf368faaa0eb51872418ffd0de4f878cf29afb1d6075aba  ← 測試裡寫的
```

`git status` 顯示這些檔**沒有被修改** —— autocrlf 就是這樣運作的。
所以這跟「參數有沒有被改」完全無關，是 checkout 設定造成的。

跑 `pytest` 會看到：

```
FAILED tests/test_frozen_reference.py::test_ref_v2_stays_frozen_at_its_original_params
... ref-v3 / v4 / v5 / v6 / v7 同樣 6 個
```

⚠️ **照 `CLAUDE.md` 的硬規則，不准為了讓它過而改期望值。** 兩條合法的修法：

1. `_sha256()` 改成先做 LF 正規化：
   `hashlib.sha256(path.read_bytes().replace(b"\r\n", b"\n")).hexdigest()`
   行尾不是 JSON 的內容，正規化後仍然抓得到改參數／改縮排／改鍵順序。
   **這條在 2026-08-19 試過並通過（36 passed），但之後被改回原狀，所以現在仍是紅的。**
2. 加 `.gitattributes`：`*.json text eol=lf`，讓 checkout 出來就是 LF。
   從根本解，但要重新 checkout 一次才生效。

**還沒決定用哪條。** 在決定之前，L0 在這台機器上是 30 passed / 6 failed，
不是 36 passed —— 接手的人不要以為是自己改壞的。
